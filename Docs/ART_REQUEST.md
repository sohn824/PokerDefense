# 아트 리소스 요청 목록

M11(아트 교체)에서 생성형 AI로 제작할 이미지 목록이다. **2026-08-12에 공통 스펙을 확정했다** — 아래 수치는 제안이 아니라 기준이다.

> **유닛 13종의 컨셉·이름·실루엣 규칙은 [DESIGN.md](DESIGN.md) §10.2~10.4가 유일한 출처다.** 여기에 중복해 적지 않는다.
> 적은 §10.5를 따른다.

**M11 검증 조건**(DESIGN §8)은 *플레이스홀더를 쓰는 세 곳이 전부 스프라이트로 대체되고 슬롯의 이름 라벨이 사라짐*이다. 세 곳은 **유닛·적·카드**로 확정했다.

---

## 1. 확정 스펙

| 항목 | 값 | 근거 |
|---|---|---|
| 스타일 | 2D 카툰 / 두꺼운 검은 아웃라인 / 채도 높은 색 / 플랫 셰이딩 | 고정 접두어로 재사용 |
| 시점 | **정면 고정.** 좌우 플립을 쓰지 않는다 | 적이 닫힌 루프를 360도로 돌고 유닛에 회전 코드가 없다 |
| 배경 | 투명 PNG. 그림자·테두리 프레임 없음 | |
| 캔버스 | 유닛 256×256 / 적 256×256 / 카드 256×358 / 아이콘 128×128 | |
| **PPU** | **256 고정** | 유닛 1칸 = 1 월드유닛이다. 정하지 않으면 씬에서 손으로 스케일을 맞추게 된다 |
| 해상도 기준 | 1080×1920 (9:16) 모바일 세로 | |

### 판별 크기 — 캔버스보다 이쪽이 진짜 조건이다

**화면에 실제로 그려지는 크기는 캔버스보다 훨씬 작다.** 1 월드유닛 = 145.5px이다.

| 요소 | 월드 크기 | **화면 px** |
|---|---|---|
| 유닛 (보드 슬롯) | 0.92 | **134** |
| 적 | 0.50 | **73** |
| 트랙 전체 | 6.8 × 4.8 | 989 × 698 |
| 배경 | 화면 전체 | 1080 × 1920 |

**유닛은 134px, 적은 73px에서 서로 구분돼야 한다.** 캔버스를 크게 잡는 것은 축소 여유를 두기 위함이지 디테일을 넣으라는 뜻이 아니다. 검증 조건이 **이름 라벨 제거**를 포함하므로, 실루엣이 실패하면 13종을 색으로만 구분하게 된다.

## 2. 고정 프롬프트 접두어

13종 간 톤이 튀지 않도록 매 생성에 그대로 붙인다.

```
2D cartoon game asset, thick black outline, high saturation, flat shading,
front-facing symmetrical view, centered, full body visible,
transparent background PNG, no text, no ground shadow, no border frame,
single character silhouette readable at small size
```

## 3. 생성 시 지켜야 할 규칙

- **구조 숫자를 실루엣으로 읽을 수 있어야 한다.** 2 / 2+2 / 3 / 3+2 / 4 (§10.2). 이것이 M11의 최대 리스크다.
- **성급이 올라도 구조 숫자를 바꾸지 않는다** (§10.4). 페어는 영원히 2, 트리플은 3, 쿼드는 4다.
- **성급 오라 오버레이를 만들지 않는다.** 슬롯의 `★` 라벨이 이미 성급을 담당한다 — §10.4의 *구조는 실루엣, 성급은 별* 두 축이 그대로 유지된다. 13종 × 3 = 39장도, 오라 1장도 필요 없다.
- **카드 문양은 유닛마다 고정 심볼 하나다.** 실제 손패 무늬에 따라 바뀌지 않는다 (§10.4).
- **적은 틴트를 전제하지 않는다.** HP 표시가 밝기 곱셈에서 체력 바로 바뀌므로(§7) 적 스프라이트는 제 색을 그대로 쓴다.
- **소버린만 실루엣을 약간 크게 잡는다** (§10.4).

## 4. 단계별 요청 목록 (총 31장)

### 1단계 — 파일럿 2장

**`Guard` 원페어 건슬링어(구조 2)** 와 **`Ranger` 투페어 트윈레인저(구조 2+2)** 둘만 먼저 만든다.

13종 중 이 둘을 고른 이유는 §10.2가 직접 *"원페어와 투페어를 시각적으로 구분한다"* 고 짚은 **최대 혼동 쌍**이기 때문이다. 134px에서 이 둘이 안 갈리면 실루엣 언어 자체가 실패이고, **13종을 만들기 전에 알아야 한다.** 스타일 레퍼런스 확보와 최대 리스크 검증을 한 번에 한다.

> **검증:** 134px로 축소해 슬롯에 나란히 놓고 **이름 라벨을 끈 채** 구분되는지 본다. 실패하면 13종 생성 전에 실루엣 규칙을 다시 짠다.

### 2단계 — 유닛 13장

1단계 이미지를 스타일 레퍼런스로 물린다. **구조가 있는 다섯을 먼저** 만들고 나머지 8종을 뒤에 붙인다.

|---|---|---|---|---|
| 1 | `Unit_Guard` | 원페어 건슬링어 | **2** 쌍권총 | Rapid |
| 1 | `Unit_Ranger` | 투페어 트윈레인저 | **2+2** 양팔 2연장 | Multi |
| 1 | `Unit_Lancer` | 트리플 마크스맨 | **3** 3총구 | Heavy |
| 1 | `Unit_Warden` | 풀하우스 배터리 | **3+2** 주포3 + 보조포2 | Splash |

| 2 | `Unit_Scout` | 하이카드 스카우트 | 카드 1장 | Rapid |

### 3단계 — 적 7장

**타입은 5종이지만 에셋은 7개이고, 개별로 만든다.** 73px에서 서로 구분되는 것이 조건이다.

| 에셋 | 타입 | HP | 특성 |
|---|---|---|---|
| `Enemy_Grunt` | Normal | 60 | 기준 |
| `Enemy_Runner` | Runner | 82 | 빠르다 (속도 4.2) |
| `Enemy_Swarm` | Swarm | 50 | 작고 많다 |
| `Enemy_Brute` | Tank | 690 | 크고 느리다 (속도 1.3) |
| `Enemy_MiniBoss` | Boss | 550 | W5 전용 |
| `Enemy_Boss` | Boss | 1300 | W10·W15·W20 |
| `Enemy_FinalBoss` | Boss | 4200 | W20 최종 |

> **미결:** 현재 코드는 적을 전부 `scale 0.5` 고정으로 그린다. 보스 3종을 크게 보이게 하려면 `EnemyDefinition`에 스케일 필드가 필요하다. 캔버스는 7장 모두 동일하게 두고, 크기 차이는 씬 스케일로 낸다.

### 4단계 — 카드 7장

**52장을 개별 생성하지 않는다.** 프레임 + 무늬 + 숫자 폰트를 런타임 합성한다.

- 카드 앞면 프레임 1장
- 무늬 아이콘 4종 (♠ ♥ ♦ ♣) — **이미지로 가면 `♦` 두부 함정이 해소된다** (Maplestory에 U+2666이 없어 `◆`로 대체 중)
- 카드 뒷면 1장
- 선택/교체 하이라이트 프레임 1장

### 5단계 — 배경·트랙 4장

**교체가 아니라 신규다.** 지금은 트랙이 아예 안 그려지고 카메라가 단색 `(0.1, 0.1, 0.12)`으로만 지운다.

- 전체 배경 1장 (1080×1920)
- 트랙 텍스처 1장 — 989×698px 영역의 닫힌 사각 루프
- 빈 슬롯 타일 1장
- 슬롯 하이라이트 프레임 1장 (배치 가능 / 머지 대상 2색은 틴트로 낸다)

## 5. M11 범위 밖

- **투사체 3종** — §5.5가 *공격은 즉시 히트, 투사체는 연출 단계*로 못 박았고 코드에 투사체가 없다. 지금 만들면 붙일 곳이 없다.
- **버튼 프레임 / HUD 아이콘 / 결과 팝업** — 검증 조건에 걸리지 않는다.
- **피격·소환·머지 이펙트, 희귀 족보 등장 연출** — 위와 같다. 연출 단계에서 §10.4의 3단계 스케일 규칙과 함께 본다.

## 6. 코드 변경이 동반되는 것

이미지만 넣어서는 끝나지 않는 항목이다.

| 변경 | 위치 | 내용 |
|---|---|---|
| **HP 밝기 → 체력 바** | `CombatScreen.SyncEnemies` | `Color.Lerp(full * 0.25f, full, ratio)` 틴트를 걷어내고 체력 바를 붙인다. 컬러 스프라이트에 0.25배를 곱하면 *죽어간다*가 아니라 *안 보인다*가 된다 |
| **이름 라벨 제거** | `UnitSlotView` | `nameLabel`을 지운다. **스프라이트가 전부 들어오고 판별을 확인한 뒤에 한다** — 먼저 지우면 색 사각형 13종을 색으로만 구분하게 된다 |
| **카드 텍스트 → 이미지** | `CardView`, `CardText` | 랭크·무늬 TMP 텍스트를 프레임 + 무늬 이미지 합성으로 바꾼다 |
| **적 스케일** (선택) | `EnemyDefinition`, `CombatScreen.CreateView` | 보스를 크게 보이게 하려면 스케일 필드가 필요하다 |

## 7. 생성 시 주의

- **투명 배경 PNG로 뽑을 것.** 배경이 들어가면 제거 공정이 추가된다.
- **동일 접두어를 고정**해서 13종 간 톤이 튀지 않게 한다.
- **좌우 플립을 쓰지 않는다.** 정면 고정이다 (§1).
- 유닛은 134px, 적은 73px로 축소해 **판별되는지 확인한 뒤** 다음 장으로 넘어간다.
