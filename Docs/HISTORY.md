## 이 문서의 관리 규칙

- **최신 항목이 위로.** 각 항목은 `날짜 — 제목` / 결정과 이유 / 검증 결과 순으로 적는다.
- **레거시 정리:** 이후 작업으로 완전히 대체되어 현재 코드·설계와 무관해진 항목은 **삭제한다.** 그 결정이 왜 뒤집혔는지가 지금도 의미 있으면 최신 항목에 한 줄로 흡수시키고, 아니면 흔적을 남기지 않는다.
- **현재 상태 요약**과 **반복 함정**은 항상 최신이어야 한다. 이력을 읽지 않아도 이 둘만으로 상태를 파악할 수 있어야 한다.
- 설계 내용 자체는 여기에 쓰지 않는다. [DESIGN.md](DESIGN.md)가 유일한 설계 출처다.

## 반복 함정

같은 곳에 두 번 이상 걸렸거나, 걸리면 원인을 찾기 어려운 것들.

| 함정 | 대응 |
|---|---|
| **폰트에 없는 글자** — `♦`(U+2666), `—`(U+2014), `–`(U+2013)이 Maplestory에 없어 두부(□)가 난다 | `◆`, `-`로 대체함. **새 기호를 쓰기 전에 `HasCharacter(c, false, true)`로 확인할 것.** Dynamic 폰트는 문자 테이블이 비어 있어 인자 없는 `HasCharacter`로는 판정이 안 된다 |
| 화면 표기에 `ToString()`을 쓰면 어긋난다 | `Card.ToString()`("4h")·`UnitInstance.ToString()`(★)은 로그·테스트용이다. 화면은 `CardText`·`BoardScreen.Describe()`가 만든다 |
| **에디터가 포커스를 잃으면 플레이어 루프가 거의 멈춘다** | `PlayerSettings.runInBackground = true`로 해결함. MCP로 실시간 동작을 볼 때 필수 |
| `manage_build`로 씬 목록을 바꿔도 디스크에 안 써진다 | `File/Save Project`를 실행해야 `EditorBuildSettings.asset`에 반영된다 |
| TMP 폰트 에셋의 아틀라스·머티리얼이 리로드 때 사라진다 | `CreateFontAsset` 후 **서브에셋으로 추가**해야 한다. TMP 기본 폰트만 바꾸면 기존 컴포넌트는 옛 폰트를 계속 문다 — 씬 전체를 갈아끼워야 함 |
| Input System 전용(`activeInputHandler: 1`)이라 기본 입력 모듈이 터진다 | `EventSystem`에 `InputSystemUIInputModule`을 붙인다 |
| 에디터를 켠 채로 패키지를 제거하면 `Library/ScriptAssemblies`에 고아 DLL이 남아 로드 실패가 쏟아진다 | 수동 삭제 후 리프레시 |
| 컨트롤러를 거치지 않고 `GridBoard`를 직접 바꾸면 화면이 굳는다 | `PlacementController`의 이벤트가 안 나가서다. 검증 스크립트를 짤 때 자주 걸린다 |
| **슬롯 인덱스로 들고 있는 전투 상태는 유닛이 움직이면 어긋난다** | 공격 쿨다운이 그랬다 — 빈 칸으로 옮기면 그 칸의 0을 물려받아 연사가 됐다(10배). 전투 중 배치가 바뀔 수 있으므로 **유닛을 키로** 들어야 한다 |
| **기존 에셋에 `[SerializeField]` 필드를 새로 넣으면 C# 초기값이 아니라 0이 들어간다** | YAML에 그 키가 없으면 Unity는 `default(T)`로 읽는다. 필드를 추가했으면 **기존 에셋에 값을 명시적으로 써 넣어야 한다** (`maxLifeDamagePerWave`가 0이 될 뻔했다) |
| 재현 실행이 필요한 검증은 손으로 하면 오래 걸린다 | `Time.timeScale`을 올리고 `EditorApplication.update`에 자동 진행 콜백을 걸면 15웨이브 완주를 1분 안에 확인할 수 있다. 콜백은 끝날 때 스스로 해제하게 짠다 |

## 이력

### 2026-08-09 — 전투 중 배치 변경을 정식 규칙으로

플레이 중 "유닛을 바꾸는 도중에 웨이브가 끝나면 포커가 스킵되는 것 같다"는 제보에서 시작했다.

- **포커 스킵은 재현되지 않았다.** 매 프레임 유닛을 옮기며(전환 시점 누적 774회) 웨이브가 끝나게 만들어도 라운드 증가·5장 드로우·교체권 5칸·확정 버튼·족보 미리보기가 전부 정상이었다.
- **하지만 전투 중에 보드가 전부 열려 있었다** — 이동·판매·조커·지원 소환이 모두 통과했다. 전투 중에도 `RoundPhase`가 `Place`로 남고 아무도 `IsFighting`을 보지 않아서다. DESIGN §1의 "페이즈는 순차적·배타적"과 어긋나는 상태였다.
- **막는 대신 정식 규칙으로 올렸다.** 적이 도는 것을 보며 배치를 고치는 것이 이 게임에서 가장 손이 바쁜 지점이고, 막으면 배치가 "전투 전에 정하고 구경하는 것"이 된다. DESIGN §1을 고쳤다.
- **그러려면 먼저 막아야 할 구멍이 있었다: 이동이 공격 쿨다운을 초기화한다.** 쿨다운을 슬롯 인덱스로 들고 있어 빈 칸으로 옮기면 그 칸의 0을 물려받는다. 같은 유닛으로 10초간 실측 — 가만히 두면 100, 매 틱 옮기면 **1000(10배)**. 위치 선택이 딜 사이클 조작이 된다. `Dictionary<UnitInstance, float>`로 바꿔 **쿨다운이 유닛을 따라다니게** 했다. 머지·조커 승급은 새 인스턴스라 쿨다운이 새로 시작하지만 재료를 소모하므로 반복할 수 없다.
- **제보한 증상의 실제 정체는 UI였다.** 유닛을 고른 채 웨이브가 끝나면 `BoardScreen.selected`가 그대로 남아, 카드 단계인데 판매·조커 버튼이 떠 있고 안내 문구가 `건슬링어 ★ 선택 - 빈 칸은 이동...`이었다. 카드는 깔렸는데 화면이 직전 단계라 건너뛴 것처럼 보인다. `RoundController.PhaseChanged`를 구독해 라운드가 열리면 선택을 놓는다.
- **검증 중에 크래시를 하나 더 잡았다.** 고른 칸의 유닛이 UI를 거치지 않고 사라지면 `Describe(null)`로 `NullReferenceException`이 쏟아진다. `Refresh`에서 빈 칸을 가리키는 선택을 버리게 했다. 선택은 UI 상태고 보드는 슬롯 탭 말고도 바뀐다.
- **검증:** EditMode **159/159**(이동으로 연사가 되지 않는지 비교하는 테스트 추가). 실플레이 — 전투 중 유닛을 고른 채 웨이브 종료 시 `selected=-1`, 버튼 숨김, 문구가 `족보를 확정하면 유닛이 소환됩니다`로 복귀, 확정 버튼 정상. 매 프레임 이동을 섞어 **5라운드 연속 진행(총 이동 5238회) 콘솔 0건.**

### 2026-08-09 — 전투 HUD: 남은 스폰 표시

- **"전멸시키면 바로 다음 라운드로"는 이미 되어 있었다.** 15웨이브를 최강 보드로 시뮬레이션해 재보니 소요 시간이 제한시간이 아니라 **마지막 스폰 시각**에 붙는다(W15: 제한 60초, 소요 24.0초, 마지막 스폰 24.0초). `UpdateOutcome`이 "스폰 완료 && 살아있는 적 0"인 틱에 바로 `Cleared`를 낸다.
- **진짜 대기 구간은 따로 있었다.** 보이는 적을 다 잡아도 **아직 안 나온 적**이 남으면 그 스폰까지 기다린다. 웨이브 15면 최종 보스를 3초에 잡고도 20초에 나오는 잔챙이 때문에 화면이 비어 있다.
- **규칙이 아니라 표기를 고쳤다.** 남은 스폰을 당기면 뜸하게 나오던 적이 한 덩어리로 몰려와 난이도가 올라간다 — 스폰 간격이 곧 웨이브 난이도다. 대신 `combatLabel`이 그 구간에 **`다음 적까지 0.2초 (남은 2)`**를 보여준다. 적이 있을 때도 아직 안 나온 수를 `(남은 n)`으로 함께 띄운다.
- `CombatContext.SecondsToNextSpawn` 하나가 늘었다. 더 나올 적이 없으면 -1이다.
- **검증:** EditMode **158/158**(테스트 1개 추가 — 전멸 후에도 `InProgress`이고 다음 스폰까지의 시간이 맞는지, 그리고 제한시간을 기다리지 않고 끝나는지). 실플레이로 대기 구간 문구 렌더링 확인(두부 0개, 새 기호 `+()` 커버리지 사전 확인). 콘솔 0건.

### 2026-08-09 — M7: 15웨이브 + 보스 + Joker

- **라이프 피해에 상한을 붙였다** (§5.4). `Life - Min(잔여, 상한)`이고 상한은 `StageDefinition`에 둔다. 상한이 없으면 Swarm 웨이브를 한 번 놓치는 순간 게임이 끝나 보드를 실험할 여지가 사라진다. 규칙은 `StageContext.LifeDamageFor` 한 곳에만 두고 화면 표기도 같은 함수를 부른다 — 두 곳에 두면 "12마리 남음, 라이프 -12"처럼 어긋난다.
- **문서에 있었지만 빠뜨릴 뻔한 규칙 하나: 보스는 한 기만 남아도 상한만큼 친다** (§5.4). 잔여 수로만 세면 보스 웨이브를 실패해도 라이프 1만 잃어 보스가 벽으로 기능하지 못한다. 보스가 이번에 처음 생겼으니 여기가 구현 시점이다. `CombatContext.UnresolvedBosses`가 늘고 `ApplyResult`가 인자 하나를 더 받는다.
- **Joker를 데이터로 붙였다.** `WaveDefinition.jokerReward`라 코드에 웨이브 번호가 박히지 않는다. **클리어해야 들어오고** 시간 초과로 넘어가면 못 받는다. 사용은 `GridBoard.TryPromoteAt` — 짝을 소모하지 않고 성급만 올리며 ★3에는 거부한다.
- **보드 탭에 네 번째 행동이 모드 없이 들어갔다.** 유닛을 고르면 판매 버튼 옆에 조커 버튼이 뜬다. 고르기 전에는 대상이 없어 아예 숨긴다.
- **웨이브 15개를 에셋으로만 만들었다** (§9.5). 코드는 한 줄도 안 바뀌었다 — `WaveDefinition`이 이미 엔트리별 `count`·`interval`·`startDelay`를 지원했다. 보스·최종 보스 적 2종을 추가하고, **`Enemy_Brute`의 타입을 Boss → Normal로 고쳤다** (진짜 보스가 생겨서 중간 탱커라는 실제 역할과 맞췄다. 이 enum으로 분기하는 코드는 0곳이다).
- **결과 화면과 재시작을 붙였다** (§9.6). 재시작은 **씬 리로드**다 — 상태를 손으로 되돌리면 새 상태가 생길 때마다 하나씩 빠뜨린다.
- **"최고 족보"를 뽑으려니 순서 기준이 없었다.** `HandCategory`의 enum 순서는 강함이 아니라(§3.3) 백스트레이트가 스트레이트보다 뒤에 있을 뿐이다. 등장 확률 순서를 `HandRarity`로 Poker에 뒀다 — 밸런스 값이 아니라 52장 덱의 조합 수라서 데이터로 뺄 이유가 없다. **"최고 유닛"은 DPS로 고른다.** 상위 족보가 모든 면에서 낫지 않으므로(§10.2) 성급만으로도 족보만으로도 정할 수 없다.
- **통계는 `RunStats`로 분리했다.** 규칙에 관여하지 않는 기록을 `StageContext`(라이프·Chip·웨이브)에 섞지 않는다.
- **테스트 18개 추가** (`StageTests`) — 피해 상한과 보스 예외, 보스 클리어/실패 시 Joker 획득 여부, ★3·빈 칸 거부, 희귀도 정렬과 전 카테고리 포함 가드, 소환 수와 최고 유닛 갱신. 기존 테스트는 `ApplyResult` 인자 추가로 호출부만 고쳤고 **기대값은 하나도 안 바뀌었다** — 잔여 적이 전부 5 이하이고 보스가 없어 상한이 결과를 바꾸지 않는다.
- **검증:** EditMode **157/157 통과**. 자동 진행 스크립트로 **15웨이브 완주** — wave 5에서 조커로 트윈레인저 ★2 → ★3, wave 10에서 건슬링어 ★2 → ★3, 라이프 11로 클리어. 결과 화면(도달 15/15, 최고 족보 투페어, 최고 유닛 트윈레인저 ★3, 총 소환 25, 사용 Chip 60)과 재시작 후 완전 초기화(라운드 1, 라이프 15, 보드 0, 통계 0) 확인. 보드를 비운 채 돌린 판은 라이프 15 → 10 → 5 → 0으로 **웨이브마다 정확히 상한만큼** 깎이고 게임 오버 화면이 떴다. 콘솔 0건.
- **남은 것:** 라운드 전환에 간격이 없어 전투 결과를 읽기 전에 다음 손패가 나온다(M5부터). 자동 진행 기준 한 판이 게임 시간 15분이라 실제로는 더 길다 — M10 밸런싱에서 볼 것.

### 2026-08-09 — M6: Chip 경제

- **유지 보너스가 이 마일스톤의 핵심이다.** 교체를 덜 쓸수록 Chip(`Max(0, 4-사용수)`). `RoundContext.UsedExchanges`가 곧 `HandSize - ExchangeableCount`라 **새 상태 없이** 계산된다. 지급은 확정 시점에 `GameFlowController`가 한다.
