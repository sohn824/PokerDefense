## 이 문서의 관리 규칙

- **최신 항목이 위로.** 각 항목은 `날짜 — 제목` / 결정과 이유 / 검증 결과 순으로 적는다.
- **레거시 정리:** 이후 작업으로 완전히 대체되어 현재 코드·설계와 무관해진 항목은 **삭제한다.** 그 결정이 왜 뒤집혔는지가 지금도 의미 있으면 최신 항목에 한 줄로 흡수시키고, 아니면 흔적을 남기지 않는다.
- **현재 상태 요약**과 **반복 함정**은 항상 최신이어야 한다. 이력을 읽지 않아도 이 둘만으로 상태를 파악할 수 있어야 한다.
- 설계 내용 자체는 여기에 쓰지 않는다. [DESIGN.md](DESIGN.md)가 유일한 설계 출처다.

## 반복 함정

같은 곳에 두 번 이상 걸렸거나, 걸리면 원인을 찾기 어려운 것들.

| 함정 | 대응 |
|---|---|
| **폰트에 없는 글자** — `♦`(U+2666), `—`(U+2014), `–`(U+2013)이 Maplestory에 없어 두부(□)가 난다 | `◆`, `-`로 대체함. **새 기호를 쓰기 전에 `HasCharacter(c, false, true)`로 확인할 것.** Dynamic 폰트는 문자 테이블이 비어 있어 인자 없는 `HasCharacter`로는 판정이 안 된다 |
| 화면 표기에 `ToString()`을 쓰면 어긋난다 | `Card.ToString()`("4h")·`UnitInstance.ToString()`(★)은 로그·테스트용이다. 화면은 `CardText`·`BoardScreen.Describe()`가 만든다 |
| **에디터가 포커스를 잃으면 플레이어 루프가 거의 멈춘다** | `PlayerSettings.runInBackground = true`로 해결함. MCP로 실시간 동작을 볼 때 필수 |
| `manage_build`로 씬 목록을 바꿔도 디스크에 안 써진다 | `File/Save Project`를 실행해야 `EditorBuildSettings.asset`에 반영된다 |

## 이력

### 2026-08-09 — M6: Chip 경제

- **유지 보너스가 이 마일스톤의 핵심이다.** 교체를 덜 쓸수록 Chip(`Max(0, 4-사용수)`). `RoundContext.UsedExchanges`가 곧 `HandSize - ExchangeableCount`라 **새 상태 없이** 계산된다. 지급은 확정 시점에 `GameFlowController`가 한다.
- **교체 중 족보 미리보기를 붙였다.** 확정 버튼이 `확정 스카우트 +4`처럼 **지금 확정하면 나올 유닛과 받을 Chip**을 보여준다. 이게 없으면 유지 보너스가 감으로 찍는 도박이 된다(DESIGN §9.1). `HandEvaluator`가 순수 함수라 비용은 없다.
- **`StageController`를 분리했다.** 라이프·Chip·웨이브는 한 판 동안 유지되는 같은 층위인데 `CombatController`가 들고 있었다. Chip은 전투가 아니라 카드·배치 단계에서 오가므로 `PlacementController`도 접근해야 한다. M7의 Joker도 여기 붙는다.
- **`EconomyDefinition` SO 신설.** 유지 보너스 상한 / 지원 소환 비용·확률·횟수 / 판매 가격. 스테이지마다 달라질 값이 아니라 `StageDefinition`과 분리했다.
- **보상 없이 버리던 Discard를 없앴다** (§7-2 닫음). 대신 판매다 — ★1/★2/★3 = 1/2/4 Chip, **유닛 종류와 무관하게 성급으로만** 정해져 외울 것이 없다.
- **`GridBoard.TryMoveSlot` 추가.** 이동과 머지를 섞지 않는다 — 유닛이 있는 칸으로는 옮길 수 없고 머지는 `TryMergeSlots`가 맡는다.
- **보드 탭이 3행동을 흡수했다.** 유닛을 고르면 빈 칸은 이동, 짝은 머지, 판매 버튼이 뜬다. 모드를 늘리지 않고 §9.4의 우려를 해소했다.
- **유닛 13종 이름을 한글 표시명으로 바꿨다** (§10.3). UI가 전부 한글인데 유닛만 영문이면 어긋난다. 에셋의 `displayName` 문자열 13개만 바뀌었다.
- **버그 하나를 잡았다.** Chip이 늘어도 지원 소환 버튼이 비활성으로 남았다 — `BoardScreen`이 `StageController.Changed`를 구독하지 않아서다. `CanSupportSummon=True`인데 버튼이 꺼져 있는 불일치를 검증 중에 발견했다.
- **테스트 24개 추가** (`EconomyTests` 20, `GridBoardTests` 이동·판매 4) — 유지 보너스 표, 지갑(부족 시 거부·잔액 불변), 판매가, 지원 소환 가중 추첨·시드 재현성·풀 밖 유닛 미출현·빈 풀 예외.
- **검증:** EditMode **139/139 통과**. 실플레이 — 2장 교체 후 확정 시 Chip +2, ★1 판매 +1, 이동, 지원 소환 2회 후 3회차 차단까지 확인. 콘솔 0건.
- **M6 검증 조건 실측 (8회 시행):** 스카우트 4기 상당 확보까지 **8, 4, 5, 4, 6, 3, 7, 5 라운드 → 평균 5.3** (M3 실측 13라운드 / 목표 4~7). **목표 범위 한가운데.**

### 2026-08-09 — 기획안 검토 및 마일스톤 재편 (M6~M10)

외부(GPT) 기획안 두 건(게임 플로우 발전, v0.2 구체화, 유닛 컨셉)을 코드와 대조해 검토하고 DESIGN §9~§12를 신설했다. **코드는 바뀌지 않았다.**

- **채택 방향:** 시스템을 늘리지 말고, 플레이어가 실제로 고민하는 두 지점(카드 교체 / 배치·머지)을 깊게 만든다.
- **가장 값이 큰 것: 유지 보너스.** 교체를 덜 쓸수록 Chip을 준다. `ExchangeableCount`가 곧 미사용 교체권이라 **새 상태 없이** "확정하고 이득을 챙길지, 포기하고 더 높은 패에 걸지"가 생긴다.
- **기획안이 빠뜨린 전제조건을 찾았다.** 유지 보너스를 판단하려면 **교체 중에 현재 족보와 소환될 유닛이 보여야 한다.** 지금은 확정 후에만 뜬다. 이대로면 감으로 찍는 도박이 된다 (DESIGN §9.1).
- **폐기한 제안: 카드 특성**(무늬·숫자가 유닛 능력을 결정). `UnitInstance.CanMergeWith`("같은 종류 + 같은 성급")와 충돌하고 — 특성을 매칭에 포함하면 머지가 사망, 무시하면 특성 선택이 무의미 — 여기에 13종 × 조합의 밸런싱 비용과 학습 비용이 더해진다. 목적("낮은 족보에도 고민 만들기")은 유지 보너스가 대신한다.
- **뒤집은 결정 2개:** 적 처치 보상 없음(경제가 웨이브 구성에 흔들리는 것을 막음, 덤으로 `EnemyDefinition` 필드 불필요), 희귀 유닛 성장은 Joker(복제 구매는 로열 스트레이트 플러시 가격이 착취되거나 무의미해짐).
- **비용 오산 정정:** 적 Runner·Tank·Swarm은 현재 `EnemyDefinition`으로 이미 표현 가능하다(Brute가 곧 Tank). `EnemyType`으로 분기하는 코드가 **0곳**이라 enum 값 추가 + 에셋 작업이다.
- **유닛 이름은 한글로 바꿨다.** UI가 전부 한글인데 유닛만 `Pair Gunslinger`면 *원페어 = One Pair = Pair* 번역을 거쳐야 해서, 이름을 기억 장치로 만들려던 목적이 깨진다. **슬롯이 145px밖에 안 되므로** 표시명(6자 이내)과 정식명을 분리했다.
- **순서는 의존 관계로 정했다.** Chip → 판매로 §7-2 해결 / 보스 → Perk / 유닛 역할 → 적 타입.
- **첫 측정 지점:** M6 직후 "스카우트 4기 = 13라운드"가 **4~7라운드**로 내려오는가.

### 2026-08-08 — M5: 라운드 루프 결합 + HUD

- **`GameFlowController`를 만들었다.** 하는 일은 작다 — 자동 구간만 맡고 플레이어 입력 구간은 각 컨트롤러가 그대로 한다. **새로 붙은 자동 전이는 `Result` → 다음 `Draw` 하나뿐**이고 나머지는 이미 자동이었다. 첫 라운드도 여기서 연다(`RoundController.Start()`의 자동 시작 제거 — 루프 주인이 둘이면 어긋난다).
- **`새 라운드` 버튼 제거.** 루프가 자동이 되면 어긋남만 만든다. 배치 도중에 누르면 대기 유닛이 조용히 사라지는 잠재 버그가 있었다.
- **`Combat` 진입 조건을 두 개로 막았다.** 연속 루프가 드러낸 구멍이다 — `Place` 페이즈여야 하고(교체 중 진입 시 소환을 통째로 건너뜀), 배치 대기 유닛이 없어야 한다(남기면 다음 소환이 덮어씀).
- **검증:** EditMode 115/115. 라운드 3회 연속 진행 — 1회차 시간 초과(라이프 20→16) → 자동 2회차 클리어 → 자동 3회차에서 **배치가 머지로 이어져 Guard ★2** 생성 후 클리어 → 전 웨이브 클리어로 루프 정지, 버튼 전부 잠김. 보드 유닛은 라운드 간 유지. 콘솔 0건.
- **남은 것:** 재시작 수단 없음(M7). 라운드 전환에 간격이 없어 전투 결과를 읽기 전에 다음 손패가 나온다.

### 2026-08-08 — 한글 폰트 적용, UI 한글화

- Maplestory TTF를 넣고 TMP 폰트 에셋 생성. **아틀라스는 Dynamic** — 한글 음절이 11,172자라 정적으로는 감당이 안 된다. Light의 굵기 표 700 항목에 Bold를 연결해 `FontStyles.Bold`가 진짜 Bold로 나온다.
- **커버리지를 먼저 확인하고 표기를 정했다.** 있음: 한글 전체·영숫자·`♠♥♣★☆◆◇` / 없음: `♦`·`♢`·`—`·`–`.
- 폰트 때문에 영문이던 세 곳을 되돌렸다: 족보명, 카드 무늬(`S/H/D/C` → `♠♥◆♣`), 성급(`*` → `★`). 나머지 UI 문구도 한글로 통일했다.
- **`CardText`를 새로 뺐다.** 키카드가 `4h`로 나와 카드 앞면(`4♥`)과 어긋났다.
- **검증:** EditMode 115/115. 실플레이로 두부 0개, 콘솔 0건.

### 2026-08-08 — M4: 웨이브 + 전투 + 클리어 판정

- **보드를 월드 스페이스로 옮겼다.** 검증 조건이었던 **"기존 87개 테스트 무수정 통과"를 충족** — 표현만 바꾸고 규칙 코드는 건드리지 않았다는 증거다. 클릭은 `Pointer` → `ScreenToWorldPoint` → `Physics2D.OverlapPoint`로 잡고, 카드 UI 위 클릭은 `IsPointerOverGameObject()`로 거른다. 누를 수 없는 칸은 `hitbox.enabled = false`로 검사에서 뺀다.
- **전투를 순수 C#으로 만들었다.** `CombatContext.Tick(float deltaTime)`이 핵심 — `deltaTime`을 인자로 받으면 고정 틱을 강제하지 않으면서 테스트에서 전투 한 판을 통째로 시뮬레이션할 수 있다. **M4 검증 조건이 그대로 EditMode 테스트가 됐다.**
- 트랙은 `GridBoard`가 계산하는 닫힌 사각 루프(반경 3.4×2.4, 길이 23.2). 적 위치는 진행도 하나이고 바퀴 수를 포함해 누적된다. 유닛 쿨다운은 `CombatContext`가 들고 있어 **`GridBoard`는 전투 상태를 모른다.**
- **`UnresolvedEnemies`는 아직 안 나온 적까지 포함한다.** 제한시간이 스폰보다 먼저 끝나면 안 나온 적도 라이프를 깎아야 한다.
- **만들지 않은 것:** 타겟팅 enum(1종 고정), 투사체(즉시 히트), 처치 보상, `TargetRegistry` 클래스.
- **검증:** EditMode 115/115(테스트 28개 추가). 실플레이 — 웨이브 1은 12.81초에 클리어(라이프 유지), 보드를 비운 웨이브 2는 시간 초과로 **라이프 20 → 8**(잔여 12만큼). 콘솔 0건.

### 2026-08-08 — M3: 그리드 + 배치 + 머지

- **`GridBoard`(순수 C#)가 15슬롯 점유와 배치·머지 규칙을 소유한다.** 거부 시 **보드를 건드리지 않는다.** `UnitInstance`는 불변이라 머지는 승급된 새 인스턴스를 만든다.
- **설계 구멍 발견: 그대로 뒀으면 ★3에 영원히 도달할 수 없었다.** 머지가 "소환 유닛을 놓을 때"만 일어나면 소환 유닛은 항상 ★1이라 ★2에 못 얹고, 보드 위 ★2 둘을 합칠 방법이 없다.
  - 처음 쓴 테스트 `board.TryPlace(0, board[1])`는 통과했지만 **UI에 그런 경로가 없었다.** 테스트가 실제 사용을 반영하지 못한 사례이고, 그 호출은 재료 슬롯을 비우지도 않아 유닛이 복제됐다.
  - `TryMergeSlots(from, to)` 추가. UI는 2탭 방식.
- **DESIGN과 달라진 것:** `GridSlot`·`MergeResolver` 클래스를 만들지 않았다. 슬롯은 `UnitInstance[]`면 충분하고 머지는 배치의 일부다. 문서를 실제에 맞게 고쳤다.
- **성급 배수는 사거리에 곱하지 않는다.** 사거리까지 늘면 배치 위치를 고르는 의미가 줄어든다.
- **§7-1 실측: 스카우트 4기를 모으는 데 13라운드.** ★3 하나에 같은 유닛 4기가 필요하므로 이 속도로는 머지가 돌아가지 않는다.
- **검증:** EditMode 87/87(테스트 26개 추가). Guard ★1 둘 머지 → **★2 ATK 28**(정확히 2배), 점유 슬롯 안 늘어남. 스카우트 넷을 이어 붙여 **★3 ATK 40** 도달. 보드 15/15에서 포기 동작까지 확인.

### 2026-08-07 — M2: 카드 UI + 드로우/교체 플로우

- **`RoundContext`(순수 C#)가 페이즈 순서를 강제한다.** 잘못된 순서로 부르면 예외. MonoBehaviour가 아니라서 UI를 통하지 않고 규칙을 검증할 수 있다.
- **교체는 자리 단위로 잠근다.** 한 라운드에 여러 번 누를 수 있지만 같은 자리는 한 번뿐이다. 나눠 바꾸게 한 이유는 **바뀐 결과를 보고 다음 선택을 하게** 만들기 위함이다. 잠긴 자리가 섞인 요청은 **손패를 한 장도 건드리지 않고** 통째로 거부한다.
- 교체가 여러 번이 되면서 "교체 끝"이 별도 동작이 되어야 했다(`FinishExchange`).
- **`RoundController`는 이벤트만 노출한다.** UI가 구독하고 입력은 메서드로 되돌려준다. Game이 UI를 모르는 상태를 유지했다.
