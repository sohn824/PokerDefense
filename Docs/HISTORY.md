## 이 문서의 관리 규칙

- **최신 항목이 위로.** 각 항목은 `날짜 — 제목` / 결정과 이유 / 검증 순으로 적는다.
- **레거시 정리:** 이후 작업으로 완전히 대체돼 현재 코드·설계와 무관해진 항목은 삭제한다. 뒤집힌 이유가 지금도 의미 있으면 최신 항목에 한 줄로 흡수시킨다.
- **현재 상태 요약**과 **반복 함정**은 항상 최신이어야 한다. 이력을 읽지 않아도 이 둘로 상태를 파악할 수 있어야 한다.
- 설계 내용은 여기 쓰지 않는다. [DESIGN.md](DESIGN.md)가 유일한 설계 출처다.
- 완성도·게임필 개선 아이디어는 [POLISH.md](POLISH.md)에 백로그로 둔다. 착수·완료 시 이 문서에 기록하고 POLISH.md에서 지운다.

## 반복 함정

같은 곳에 두 번 이상 걸렸거나, 걸리면 원인 찾기 어려운 것들.

### Unity / 코드

| 함정 | 대응 |
|---|---|
| **폰트에 없는 글자** — `♦`(U+2666), `—`, `–`이 Maplestory에 없어 두부(□) | `◆`, `-`로 대체. 새 기호 전에 `HasCharacter(c, false, true)`로 확인(Dynamic 폰트는 인자 없는 `HasCharacter`로 판정 불가) |
| 화면 표기에 `ToString()` | `Card.ToString()`("4h")·`UnitInstance.ToString()`(★)은 로그·테스트용. 화면은 `CardText`·`BoardScreen.Describe()` |
| **에디터 포커스를 잃으면 플레이어 루프가 거의 멈춘다** | `PlayerSettings.runInBackground = true`. MCP로 실시간 동작 볼 때 필수 |
| `manage_build`로 씬 목록 바꿔도 디스크에 안 써짐 | `File/Save Project` 실행해야 `EditorBuildSettings.asset`에 반영 |
| **TMP 폰트 에셋 아틀라스가 리로드·씬 저장 때 부푼다** | 다이나믹 폰트라 `Maplestory Light/Bold SDF.asset`이 1×1 → 1024² 커밋 상태로 바뀐다. 무관한 churn이면 `git checkout`으로 되돌린다. 폰트를 새로 만들 땐 `CreateFontAsset` 후 **서브에셋으로 추가** |
| Input System 전용(`activeInputHandler: 1`)이라 기본 입력 모듈이 터짐 | `EventSystem`에 `InputSystemUIInputModule` 부착 |
| 에디터 켠 채 패키지 제거 → `Library/ScriptAssemblies`에 고아 DLL | 수동 삭제 후 리프레시 |
| 컨트롤러 안 거치고 `GridBoard` 직접 변경 → 화면 굳음 | `PlacementController` 이벤트가 안 나가서다. 검증 스크립트에서 자주 걸린다 |
| **슬롯 인덱스로 든 전투 상태는 유닛이 움직이면 어긋난다** | 공격 쿨다운이 그랬다 — 빈 칸으로 옮기면 그 칸의 0을 물려받아 연사(10배). **유닛을 키로** 들 것 |
| **기존 에셋에 `[SerializeField]` 필드를 새로 넣으면 C# 초기값이 아니라 0** | YAML에 키가 없으면 `default(T)`. 필드 추가 시 기존 에셋에 값을 명시적으로 써넣고, **비어 있지 않은지 검사하는 에셋 가드 테스트**를 붙인다(`visualScale`·`multiSpread`가 그랬다) |
| **`Awake`에서 만든 것을 다른 컴포넌트의 `Awake`가 읽으면 순서에 걸린다** | 실행 순서는 씬 설정에 달려 코드만 봐선 안 보인다. **처음 묻는 쪽이 만들게**(지연 생성) |
| **enum 값을 중간에 끼우면 기존 에셋이 조용히 어긋난다** | 에셋은 enum을 정수로 든다. `EnemyType`은 뒤에만 붙이고(Normal 0 / Swarm 1 / Boss 2 / Runner 3 / Tank 4) 정수 값 고정 테스트 |
| `Tick(0.05f)`를 N번 돌려도 정확히 N×0.05초가 안 됨 | 부동소수 누적이라 살짝 못 미쳐 제한시간 판정을 안 지난다. 한 스텝 더 돌린다 |
| 스크립트로 씬 `RectTransform` 옮길 때 `localPosition` | 직렬화되는 건 `m_AnchoredPosition`. `anchoredPosition`에 쓰고 `RectTransform`도 `SetDirty` |
| **"콘솔에 오류 없음" ≠ "컴파일됨"** | `refresh_unity`가 파일 변경을 못 잡으면(`refresh_triggered: false`) 컴파일 자체가 안 돈다 — 콘솔은 깨끗하고 `execute_code`는 옛 어셈블리를 본다. **`Library/ScriptAssemblies/Assembly-CSharp.dll` 수정 시각을 소스와 비교.** 안 돌았으면 `AssetDatabase.ImportAsset(path, ForceUpdate)` + `CompilationPipeline.RequestScriptCompilation()` |
| **플레이 모드에서는 에셋 갱신·저장이 막힌다** | `refresh_unity`가 30초 타임아웃. 에디터 상태의 `is_playing`을 먼저 볼 것. 플레이 중엔 Unity를 안 건드리는 작업(분할·측정·검산)을 먼저 |
| **플레이 모드에서 만든 오브젝트는 나가는 순간 사라진다** | 씬 편집 전 `Application.isPlaying` 확인. `SerializedObject`로 씬 저장 시 `This cannot be used during play mode` |
| **라벨 넘침을 rect 폭으로 판단하면 틀림** | TMP는 자동 개행이라 넘치면 밖으로 안 나가고 두 줄이 되어 아래를 침범한다. `textBounds`는 개행 후 값이라 항상 rect 안. **`GetPreferredValues`로 재고 `textInfo.lineCount`가 1인지** |
| 에디트 모드에서 뷰 `Show()` 미리보기 → 그대로 씬에 저장됨 | TMP 문자열·색이 직렬화된다. 찍어 본 뒤 `Show(null)`로 되돌리고 저장 |
| **`TMP_Text.fontMaterial` getter가 인스턴스 머티리얼을 만든다** | 진단 스크립트에서 `.fontMaterial`을 읽기만 해도 그 TMP에 로컬 머티리얼이 붙고, 다음 `SaveScene`에 `m_fontMaterial`이 공유 머티리얼 링크를 끊은 채로 직렬화된다(라벨 여럿에 번져 씬 diff가 커진다). 읽기는 `.fontSharedMaterial`로. 이미 번졌으면 씬을 `git checkout` 후 의도한 변경만 다시 적용 |
| **성급 배수는 공격력·공격속도에 동시에 곱해져 DPS가 제곱으로 커진다** | `{1, 1.6, 2.25}`면 DPS ×1 / ×2.56 / ×5.06. 배수를 만질 때는 항상 제곱해서 볼 것 |
| **`spriteAlignment`는 `TextureImporter`에 없다** | `TextureImporterSettings`에 있다. MCP `manage_asset`으로 넘기면 성공 반환 후 조용히 무시(피벗이 Center로 남아 유닛이 슬롯에서 뜬다). `ReadTextureSettings`→수정→`SetTextureSettings`→`SaveAndReimport`, 메타 되읽어 `alignment: 7` 확인 |
| 스프라이트 전환 전 텍스처 높이를 읽으면 NPOT 값 | 407×749인데 `tex.height`가 512. `textureType = Sprite` + `npotScale = None` 먼저 걸고 리임포트 후 다시 읽는다 |
| **`.meta`를 지우고 이미지를 덮어쓰면 GUID는 살아도 임포트 설정이 초기화** | 참조는 안 끊겨 조용하다. `textureType` Default·PPU 100·NPOT 켜짐으로 돌아간다. `.png`만 덮고 `.meta`는 둔다. 덮었으면 메타에서 `textureType: 8`·PPU 확인 |
| **채팅 미리보기의 흰/검은 배경은 투명 여부를 말해주지 않는다** | 파일을 직접 읽어 알파 채널을 확인하기 전까지 배경 판정 보류 |

### 밸런스 측정

| 함정 | 대응 |
|---|---|
| **사거리는 자유롭게 못 내린다** | 가운데 세 칸(6·7·8)이 트랙에서 2.40 떨어져 그 아래면 아무것도 못 때린다. 게임 최단이 2.5인 이유. 크기는 덮는 트랙 비율로 잰다 — 15칸 평균이 2.5에서 24.0% / 3.0에서 36.6% / 3.5에서 51.6% / 4.0에서 66.3% |
| **사거리와 관통 길이를 따로 보정하면 어긋난다** | 둘 다 "한 발이 몇 기를 때리느냐"에 걸린다. 명목 DPS로 맞추지 말고 **유효 피해량**(스폰 HP − 잔여 HP, 오버킬 제외)으로 맞춘다 |
| **오버킬은 명목 DPS가 아니라 ATK의 절대 크기에 달렸다** | 패턴 비교 시 명목 DPS를 낮게 정규화하면 오버킬이 안 일어나 반대 결론이 난다. 실제 유닛 ATK 대역(5~310)에서 잰다 |

### 2026-08-09~10 — M6~M9: Chip 경제 / 웨이브·보스·Joker / 유닛 패턴·적 타입 / 딜러 특전

구조는 전부 DESIGN.md에 있다. 이때 정한 것 중 코드에 안 드러나는 것:

- **M6 Chip 경제.** 유지 보너스가 핵심 — `ExchangeableCount`가 곧 미사용 교체권이라 새 상태 없이 계산. `StageController` 분리(라이프·Chip·웨이브는 한 판 유지되는 같은 층위). 판매가는 성급으로만(1/2/4). **M6 검증:** 스카우트 4기 확보까지 평균 5.3라운드(M3의 13 → 목표 4~7 한가운데).
- **M7 웨이브·보스·Joker (에셋만, 코드 0줄).** 라이프 피해 상한(§5.4), 보스는 한 기만 남아도 상한만큼. 최고 족보는 `HandRarity`, 최고 유닛은 DPS. `RunStats` 분리(규칙에 관여 안 함). 재시작은 씬 리로드.
- **M8 공격 패턴 5종 + Runner·Tank.** 패턴이 바꾸는 건 "몇 기를 때리는가"뿐, 겨냥 대상은 항상 사거리 내 가장 앞선 1기. Rapid↔Heavy는 코드가 같고 오버킬 낭비로만 갈린다. Pierce는 트랙 기준, Splash는 착탄 지점 기준. `EnemyType`은 뒤에 붙였다(정수 고정). 스탯은 기준 DPS 유지하고 배분만 옮김.
- **M9 딜러 특전.** 6종이 건드리는 곳 5개를 `PerkSet` 메서드 5개로 고정, 호출부는 "지금 값이 얼마인가"만 묻는다. `PerkSet`은 `StageContext`가 소유(규칙을 바꾸므로). `AttackPowerOf`를 `UnitInstance`에 안 넣음(유닛은 스테이지를 모르는 불변, 전투 피해와 상세 표기가 반드시 같은 수여야 함). 특전마다 SO 없이 전역 `PerkTable` 1개. 화면 이름은 한글 하나(뚝심·위로금·흥정·이자·신병 훈련·고참), `PerkId`는 영문.

### 2026-08-06~09 — M0~M5: 포커 코어 / 카드 UI / 그리드·머지 / 전투·웨이브 / 라운드 루프

구조는 DESIGN.md. 이때 정한 것 중 코드에 안 드러나는 것:

- **M0 asmdef 전면 폐지.** "불가능"이라던 판단이 틀렸다 — Test Runner는 asmdef가 아니라 `nunit.framework`를 참조하는 로드된 어셈블리를 스캔하고, 필요한 참조 방향(`Assembly-CSharp-Editor` → `Assembly-CSharp`)은 predefined끼리 자동 성립. 폴더명만 `Editor`로. 포기: `[UnityTest]`·`LogAssert`·PlayMode 테스트·컴파일러의 레이어 강제.
