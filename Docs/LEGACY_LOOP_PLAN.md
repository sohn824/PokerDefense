## 14. 다음 기획안 — 선택의 근거와 한 판의 흐름 (2026-09-06)

> **2026-09-08 구현 대조:** 위협 텍스트·역할/머지 안내·결과 비트·Act 예고는 구현됐다. 잔여 적 종류별 회고·중단 복구·개인 기록은 미구현 제안이다. §0~13의 확정 규칙을 유지한다. 아래 시간·검증 기준은 첫 프로토타입의 가설이며 밸런스 확정값이 아니다. 이번 검토는 문서·코드·에셋 대조이며 실제 플레이 관찰을 대신하지 않는다.

### 14.1 핵심 경험과 현재 진단

**다가올 위협을 읽고, 손패를 어디까지 바꿀지 판단하고, 만들어 낸 카드 군단으로 버틴다.** 좋은 족보가 뜬 순간뿐 아니라, 필요한 유닛을 스스로 만든 순간이 기억에 남아야 한다.

| 확인된 현재 상태 | 기획상 의미 |
|---|---|
| `RoundScreen.ShowPreview`가 현재 족보·소환 유닛·유지 보너스를 표시 | 선택 결과는 보인다. 다음 적과 보드의 필요를 연결하면 판단의 근거가 생긴다 |
| `ThreatPreview`가 준비 중 이번 적을 종류별 수량 텍스트로 표시 | 구성은 보인다. 적 특성과 내 유닛 역할을 연결하는 설명은 남았다 |
| `RoundBreakScreen`이 일반 전투 종료 후 1.8초 자동 진행·탭 스킵을 제공 | 결과를 읽을 틈은 생겼다. 다음 준비에서 다시 보는 기록과 누적 대기시간 검증은 남았다 |
| 상점은 클리어한 5의 배수 웨이브 뒤에만 열림 | 실패하면 카드 보정 기회도 놓친다. 실패 연쇄의 체감은 사람 플레이로 확인해야 한다 |
| `RunStats`는 최고 족보·최고 명목 DPS 유닛·소환 수·총 지출을 기록 | 성과는 보이나 무엇이 이번 전투에서 부족했는지는 설명하지 못한다 |
| 50웨이브의 실제 플레이 시간 미측정, Scripts에 런 저장·복구 경로 확인되지 않음 | 모바일에서 한 판을 끝내기 위한 시간 부담과 중단 손실을 검증해야 한다 |

### 14.2 1순위 — 이번 위협을 보고 손패를 고른다

**노출 시점:** 새 손패가 나오는 Exchange 시작부터 Place 종료까지. 교체를 마친 뒤 처음 보여주면 이미 결정을 끝낸 상태라 늦다.

- 상단에 이번 라운드 번호, 적 아이콘·수량, 제한시간, 보스 여부를 표시한다. 문구는 “다음 웨이브” 대신 “이번 전투”로 통일한다.
- 숫자는 `Stage.CurrentWave.Entries`를 적 종류별로 합산한다. 첫 버전은 별도 위험도 점수나 승률 예측 없이 실제 구성만 보여준다.
- 적 아이콘을 누르면 이동 특성과 대응 원리 한 줄을 보여준다. 예: “빠르게 이동합니다. 사거리 안에서 공격할 시간을 확보하세요.” 특정 유닛을 정답으로 강요하지 않는다.
- 현재 족보 프리뷰에 소환 유닛의 역할 한 줄과 **즉시 머지 가능 여부**를 붙인다. 머지는 동일 종류·동일 성급이라는 실제 규칙으로 판정한다.
- 교체할 카드를 고르면 실행 후 유지 보너스도 미리 보여준다. 아직 실행하지 않은 선택만으로 Chip을 차감하지 않는다.
- 보유 카드 선택 중에는 손패 칸을 대상으로 미리보기만 제공하고, 실제 배치 전까지 소모하지 않는다. 새 확인 팝업은 추가하지 않는다.

**예시:** 이번 전투에 군집 적이 많고 보드에 투페어 ★1이 있을 때, 현재 투페어를 확정해 머지를 만들지, 교체해서 다른 공격 역할을 노릴지, 보유 카드를 쓸지 비교한다. 어느 선택이 강한지는 사거리·밀집도·성급에 달려 있으므로 UI가 “최적”이라고 단정하지 않는다.

**완료 기준:** 처음 보는 플레이어가 카드 교체 전에 이번 적의 주된 특성을 말할 수 있고, 현재 손패를 유지하거나 바꾼 이유를 설명할 수 있다. 작은 화면에서 손패·확정 버튼을 가리지 않아야 한다.

### 14.3 2순위 — 전투 결과를 읽고 다음 선택에 연결한다

- **현재 구현은 1.8초 자동 진행 + 탭 스킵이다.** 최초 0.6~0.9초 가설은 구현값으로 대체한다. 일반 웨이브 종료에는 짧은 결과 비트를 제공한다. 성공은 “라운드 클리어”, 실패는 “시간 초과 · 라이프 -N”으로 명확히 구분한다.
- 보상은 실제 지급된 항목만 표시한다. 적 처치 Chip은 없고, 유지 보너스는 족보 확정 때 이미 받은 재화이므로 종료 시 다시 획득한 것처럼 연출하지 않는다.
- 상점 웨이브는 **결과 → 상점 → 새 손패**, 최종 승패는 **결과 화면**으로 이어진다. 자동 진행·탭 건너뛰기가 동시에 일어나도 정산과 다음 라운드 시작은 한 번만 실행돼야 한다.
- 실패 시 남은 적 종류·수량과 보스 잔존 여부를 결과 스냅샷에 담아 다음 준비 단계까지 접어 볼 수 있게 남긴다. “범위 딜 부족” 같은 원인 단정은 실제 기여 측정 전에는 하지 않는다.
- 딜음은 결과가 끝나고 새 손패가 실제로 나타날 때 한 번 재생한다. 결과음·상점음·딜음이 한 프레임에 몰리지 않게 전이와 맞춘다.

**완료 기준:** 플레이어가 라이프가 줄어든 이유와 이번 보상을 구분한다. 50회 누적되는 연출 시간이 부담스럽지 않은지 측정하고, 건너뛰어도 정산은 동일해야 한다.

### 14.4 3순위 — 50웨이브를 다섯 구간으로 읽게 한다

- **현재는 결과 비트의 다음 Act 예고만 구현했다.** 5칸 진행 바는 사용자 판단으로 제거했다. 상시 진행 바 재도입은 예정하지 않으며, 위치 인지가 어렵다는 관찰이 있을 때 기존 라운드 라벨 보완부터 검토한다.
- Act 2~5 시작은 **W11·21·31·41**이다. 별도 닫기 버튼 없이 짧은 배너를 결과 전환 안에 넣는다.
- 각 Act가 어떤 판단을 시험하는지 기존 적 구성에 맞춰 전달한다: 기본 배치 → 혼합 대응 → 고체력 적 대응 → 성장·공간 운영 → 종합 검증. 신규 상태이상이나 상성 시스템 없이 기존 패턴·스폰 간격으로 차이를 낸다.
- 보스는 이전 라운드 준비 때도 다가오는 목표로 예고한다. 보스 직전에는 상점이 항상 있는 것이 아니므로 구매 기회를 보장하는 문구를 쓰지 않는다.
- 현재 길이를 먼저 측정한다. 준비·전투·상점·연출 시간을 분리해서 병목을 찾고, 이후 웨이브 수 축소 또는 배속을 별도 실험한다. 전투 중 보드 조작이 가능하므로 배속이 조작 부담까지 바꾼다는 점을 함께 검증한다.

### 14.5 모바일 완주와 재도전

**중단·재개는 외부 테스트 확대 전 검토할 별도 작업이다.** 메타 성장과 달리 진행 중인 한 판을 보존하는 기능이다.

- 권장 첫 범위는 준비·상점 단계 체크포인트. 저장에 손패, 덱/난수 상태, 자리 잠금과 교체 횟수, 보유 카드, 보드·배치 대기 유닛, 재화, 웨이브, 상점 진열·구매 상태, 기록을 포함한다.
- 단순히 웨이브 시작만 저장하면 종료·재접속으로 카드나 상점을 다시 뽑는 문제가 생긴다. 구매·교체 등 확정 행동 뒤의 상태도 보존하는 정책이 필요하다.
- 전투 중 중단 시 해당 전투 직전 상태로 복구하는 방안을 우선 검토한다. 전투 도중 이동·머지·판매까지 정확히 복구하려면 범위가 커지므로, 재도전 허용 여부와 UI 설명을 함께 결정한다.
- 저장 버전·손상 처리·게임 종료 시 런 저장 폐기를 포함한다. 구현 전에는 이어하기를 제공한다고 표시하지 않는다.
- 결과 화면은 현재 기록에 더해 이전 최고 도달 라운드와 비교하는 로컬 기록을 검토한다. 패배 원인은 마지막 전투의 관측 사실을 보여주고, 명목 DPS가 높은 유닛을 “실전 MVP”라고 부르지 않는다.

**첫 관찰 제안:** 포커 숙련도가 다른 3~5명이 각 1런을 플레이한다. 이는 이해도·불편 발견용이며 클리어율 추정 표본으로 쓰지 않는다. W5·10·20과 종료 시점에 선택 이유, 상점 카드 사용 이유, 막힌 지점, 다시 하고 싶은 이유를 짧게 묻는다.

기록할 항목은 단계별 시간, 교체 장수, 족보, 보유 카드 구매·사용, 랜덤 소환, 머지·Joker, 라이프 손실·잔여 적 구성이다. 상점 미방문은 스킵과 해당 웨이브 실패를 구분한다. 밸런스 비교가 필요해지면 재현 가능한 같은 시드와 별도 새 시드로 비교한다.

**보류할 확장:** 덱빌딩·장비·특전 복원·상태이상·메타 능력치 성장·엔드리스. 지금은 기존 선택을 이해하고 끝까지 즐기는지가 먼저다. 특히 상점 가격 인하·공짜 구제는 과거 무교체 전략 강화 사례가 있으므로, 위 개선 후에도 운 때문에 선택이 무의미한 장면이 반복되는지 관찰한 뒤 별도 설계한다.

## 15. UI/UX 개편안 — 운빨존많겜 참고 검토 (2026-09-06)

> **2026-09-08: UX-01~08 주요 코드·씬 반영 확인.** 아래는 개편의 설계 기준이며 모든 수용 조건이 검증됐다는 뜻은 아니다. 구현 상태와 남은 검증은 POLISH의 상태표를 따른다. 사용자가 요청한 UI/UX 개선에 집중하며 §14보다 구체적인 화면·입력 기준을 정한다. 기존 게임 규칙은 유지한다. §9.4의 두 탭 보드 조작은 유지하되 목적지 표시는 아래처럼 세분화한다. UX-01~08 이후 실행 순서는 §16에 정리한다.

### 15.1 참고 근거와 가져올 요소

참고: [터치TV — 운빨가이드 쇼츠](https://www.youtube.com/shorts/K5AO68ELsoM). 브라우저에서 재생·일시정지하며 초반 소환 장면과 후반 재화 획득 장면을 확인했다. 영상 편집 자막이 상단·중앙을 많이 가린다. 아래 관찰은 보이는 범위에 한정하며, 현재 출시 버전의 전체 UI나 흥행 원인을 입증하는 자료로 취급하지 않는다. 판매 제스처·확인 단계·전체 메뉴 구성은 이 영상만으로 확정하지 않는다.

| 영상에서 확인한 것 | 우리 프로젝트에 적용할 해석 |
|---|---|
| 하단의 큰 소환 버튼 안에 비용이 함께 표시됨 | 행동 이름과 비용·이득을 한곳에서 읽게 한다 |
| 재화와 유닛 수가 하단 액션 가까이에 모여 있음 | 구매·소환 판단 중 시선이 화면 끝과 끝을 왕복하지 않게 한다 |
| 전투 보드와 하단 조작 영역이 구분됨 | 전투 관찰 영역과 현재 단계 조작 영역의 경계를 고정한다 |
| 재화 획득 때 +숫자 팝업과 보유량 변화가 보임 | 행동 직후 무엇이 바뀌었는지 작은 국소 피드백으로 연결한다 |
| 소환·강화 버튼의 크기·채움이 다름 | 주 행동과 보조 행동의 시각적 우선순위를 둔다 |

이것은 외형 복제가 아니라 정보 배치 원리의 차용이다. 협동 보드, 운빨 뽑기 재화, 미션 보상, 반복 소환 비용 체계는 우리 포커·유지 보너스 경제에 바로 이식하지 않는다. 확률·등급 아이콘도 필요할 때만 보여주며, 손패 판정을 확률 숫자 나열로 대체하지 않는다.

### 15.2 개편 전 문제와 설계 근거 (2026-09-06)

**아래 표는 개편 전 진단이며 현재 결함 목록이 아니다.** 2026-09-08 코드·씬 반영 상태는 POLISH를 참조한다.

확인 자료: `Artifacts/UIUXReview/exchange-ui.png` (Unity Play Mode, 라운드 1 교체 단계). 이 화면과 다음 코드를 대조했다: `RoundScreen`, `CardView`, `BoardScreen`, `ShopScreen`. 런 전체 및 실제 휴대폰 터치 검증은 아직 하지 않았다.

| 문제 | 근거 | 바꿀 방향 |
|---|---|---|
| 지금 누를 행동이 분산됨 | 교체 단계에도 랜덤 소환·전투 시작 버튼이 별도 위치에 보임 | 단계별 하단 액션 영역으로 통합 |
| 설명의 위치와 위계가 불분명 | 보드 안 소환 안내, 보드 아래 큰 족보명, 별도 긴 상태 문장 | 보드 안내를 하단 상황 카드로 모으고 제목·역할·상태를 분리 |
| 버튼과 카드의 재질·형태가 다름 | 장식 카드 프레임과 청·녹·보라·주황 단색 버튼 | 카드 군단 테마의 공통 패널·버튼·상태 토큰 |
| 카드 잠금 이유를 읽기 어려움 | `CardView`는 선택 프레임과 interactable만 제공 | 교체 대상·교체 완료·보유 카드 배치 완료 상태 구분 |
| 목적지의 결과가 구분되지 않음 | `BoardScreen.Refresh`는 선택 후 모든 칸을 같은 방식으로 강조 | 이동·머지·자리 교환마다 형태·아이콘 구분 |
| 상세 정보가 한꺼번에 많음 | 유닛명 아래 패턴·공격력·빈도·DPS·사거리를 한 줄에 표시 | 역할·성급을 우선, 수치는 접는 상세로 이동 |
| 상점 카드 확인이 곧 소비임 | `ShopScreen.Awake`의 카드 클릭이 바로 `Buy` 호출 | 카드 선택과 명시적 구매 버튼을 분리 |
| 구매 완료와 일반 선택이 비슷함 | 구매한 카드를 `SetSelected`로 표시 | 구매 완료 체크와 빈 진열 상태를 별도로 표시 |
| 실행 불가 이유가 약함 | 랜덤 소환·조커는 주로 비활성 처리, 보드의 실패 입력은 안내 없이 끝날 수 있음 | 버튼 옆 사유 및 대상 근처 짧은 피드백 |

### 15.3 화면 구조 — 고정된 위치에서 단계만 바뀐다

아래는 배치 관계를 설명하는 와이어프레임이다. 픽셀 크기는 실제 Safe Area·텍스트 측정 후 결정한다. 보드를 줄여 모든 정보를 넣지 않는다.

```text
┌─────────────────────────────────┐
│ 라이프      구간·라운드      메뉴 │  런 상태
│ 이번 전투: 적 구성 · 보스 예고    │  준비: 위협 / 전투: 시간·잔여 적
├─────────────────────────────────┤
│                                 │
│        전투 트랙 + 15칸 보드      │  안내 문구로 칸을 가리지 않음
│                                 │
├─────────────────────────────────┤
│ 상황 카드: 족보 → 유닛 · 역할     │  선택 유닛 상세와 같은 자리 사용
│ 보유 카드 0/3       Chip · Joker │
│          손패 카드 5장           │  교체 단계
│ [선택 2장 교체] [이 손패 확정 +1]│  주 행동 위치 고정
└─────────────────────────────────┘
```

- 라이프·진행은 상단, Chip·Joker와 행동 비용은 하단에 묶는다. 재화의 숫자 원천은 하나이며 각 화면이 별도로 계산하지 않는다.
- 진행 표시는 작게 유지한다. 매 라운드 크게 필요한 정보는 이번 적·이번 손패·이번 행동이다.
- 보드에서 유닛을 선택하면 상황 카드만 해당 유닛 정보로 바뀐다. 카드를 고르는 도중 보드를 살펴봐도 손패의 교체 선택은 보존한다. 보드 선택 해제 시 손패 프리뷰로 돌아온다.
- 랜덤 소환은 Place 단계(준비 + 전투)의 보조 행동이다. 전투 중에도 버튼을 띄우되, 라운드당 1회 제한이라 이미 썼으면 사유와 함께 비활성으로 둔다.
- 전투 중 손패 영역은 접고 선택 유닛의 조작 영역으로 쓴다. 패널 변화 중 같은 손가락 입력이 새 버튼까지 통과하지 않도록 한다.

| 단계 | 우측 주 행동 | 보조 행동·상태 |
|---|---|---|
| Exchange | 이 손패 확정 +보너스 | 선택 N장 교체, 보유 카드 사용. 전투 시작·랜덤 소환은 숨김 |
| Place, 배치 대기 있음 | 유닛을 배치하세요 (실행 불가) | 배치 가능 칸 표시, 대기 유닛 판매 +반환액 |
| Place, 배치 완료 | 전투 시작 | 랜덤 소환 · Chip 비용 · 남은 횟수 |
| Combat | 전투 중 (비버튼 상태 표시) | 랜덤 소환 · 남은 횟수. 유닛 선택 시 이동·머지 안내, 판매·Joker |
| Shop | 선택 카드 구매 · 비용 | 선택 카드 없음/공간 부족/Chip 부족 사유, 상점 나가기 |

주 행동은 크기·명도·위치로 강조하고 보조는 낮은 대비의 테두리형으로 둔다. 전투 시작으로 바뀔 때 패널 이동을 최소화하며, 확정 버튼을 연타해 의도 없이 전투까지 시작하지 않게 입력을 소비한다.

### 15.4 카드 조작 — 상태를 설명 없이도 구분한다

- 기본 카드는 숫자·무늬의 가독성을 우선한다. 화려한 프레임은 가장자리로 제한하고 별도 배경판 위에 다섯 장을 정렬한다.
- **교체 대상:** 살짝 올라온 카드 + 체크 + “교체” 표시. 다시 탭하면 해제. 색만 바꾸지 않는다.
- **교체 완료:** 자물쇠 + “교체 완료”. 선택된 카드처럼 보이면 안 된다. 숫자·무늬는 계속 읽을 수 있게 유지한다.
- **보유 카드로 배치한 자리:** 같은 잠금 형태에 “배치 완료”. 유지 보너스를 깎는 교체와 구별한다.
- **보유 카드 선택:** 트레이 카드에 선택 테두리, 손패의 유효 목적지에 배치 표식, 취소 버튼. 같은 트레이 카드 재탭도 취소한다. 잠긴 카드는 “이번 라운드 변경 완료”로 안내하고 소모하지 않는다.
- 모바일에서는 hover가 없으므로 목적지 미리보기는 필수 선행 단계로 강제하지 않는다. 기본은 현재의 트레이 탭 → 손패 탭을 유지하고, 길게 누르기는 선택적인 정보 확인 수단만 된다.
- 교체 버튼에는 선택 장수, 확정 버튼에는 현재 보너스, 버튼 근처에는 “선택한 카드 교체 시 보너스 +X → +Y”를 표시한다. 현재 보너스와 예상 보너스를 혼동하지 않는다.
- “남은 교체 5칸 (자리당 1회)” 긴 문장을 상시 반복하는 대신 잠금 표시·짧은 “변경 가능 N장”을 쓰고, 첫 교체 때만 자리당 1회 규칙을 안내한다.

### 15.5 보드 조작 — 누르기 전에 결과가 보인다

기본 두 탭 입력을 유지한다. 드래그는 이후 선택적 대체 입력으로 검토하며 필수로 만들지 않는다.

| 대상 | 표시 | 실행 결과 |
|---|---|---|
| 선택한 유닛 | 굵은 테두리 + 선택 표식 | 다시 누르면 선택 해제 |
| 빈 칸 | 열린 모서리 + 이동 화살표 | 이동 |
| 머지 가능한 유닛 | 두 별이 합쳐지는 표식 + 도착 성급 | 해당 칸으로 머지 |
| 머지 불가능한 다른 유닛 | 양방향 화살표 | 자리 교환 |
| 대기 유닛을 놓을 수 없는 칸 | 강조 없음, 입력 시 짧은 이유 | 상태 유지, 소비 없음 |

- 빈 배경 탭·취소 버튼으로 선택 해제한다. UI 위 탭이 보드 이동으로 처리되지 않게 터치 ID와 UI 이벤트 차단을 실기기에서 확인한다.
- 이동·머지의 실패에는 선택을 유지해 다른 대상을 고를 수 있게 한다. 새 라운드 전환과 선택 유닛 소멸 시에는 해제한다.
- 유닛 상세는 이름·성급·공격 역할을 우선 표시하고, 공격력·공격 빈도·명목 DPS는 펼친 상세에 둔다. 선택 중 실제 사거리 표시를 제공하되 다른 슬롯 탭을 막지 않는다. “예상 기여” 수치는 검증된 전투 측정 없이는 표시하지 않는다.
- 판매는 `판매 +N Chip`, Joker는 `★1 → ★2 · Joker 1`처럼 결과·소비를 명시한다. 판매 버튼은 주 행동과 떨어뜨린다. 고성급·희귀 유닛 판매의 추가 확인은 오판매 관찰 후 적용 여부를 결정하고, 모든 판매에 팝업을 붙이지 않는다.
- 보드가 꽉 찼을 때는 현재 규칙에 맞게 대기 유닛 판매와 가능한 머지를 안내한다. 기존 유닛 판매를 대기 중에도 허용하려면 별도 규칙·컨트롤러 변경이 필요하므로 UI만으로 가능하다고 표시하지 않는다.

### 15.6 상점과 버튼 상태

- 상점 카드 탭은 선택이다. 선택 카드·가격·구매 후 잔액을 확인한 뒤 하단 구매 버튼으로 한 장을 산다. 추가 확인 모달 없이 구매 의도를 명확히 한다.
- 현재 보유 카드의 실제 숫자·무늬와 빈 슬롯을 함께 보여준다. 다음 손패는 아직 뽑히지 않았으므로 미래 족보 완성을 약속하는 추천을 하지 않는다.
- 구매 후 진열에는 “구매 완료” 체크, 보유 트레이에는 카드 도착, 재화에는 감소량을 보여준다. 구매 버튼은 선택 해제하고 연타가 다음 카드 구매로 이어지지 않게 한다.
- Chip 부족·보유 3장 가득 참·이미 구매함은 서로 다른 문구로 표시한다. 카드 선택과 정보 확인은 막지 않고 구매 실행만 막는다.
- 상점 닫기는 “상점 나가기”. 닫으면 다음 라운드라는 짧은 설명을 붙인다. 매번 팩 오프닝을 강제로 기다리게 하지 않는다.
- 버튼 상태는 기본/눌림/선택/실행 불가/처리 중으로 통일한다. 실행 불가 상태에도 사유를 읽을 수 있어야 하며 회색만으로 설명하지 않는다. 연속 입력으로 재화·교체·정산이 중복되지 않아야 한다.

### 15.7 시각 규칙과 검증

- 테마는 어두운 경기장과 카드 군단을 유지한다. 패널은 저채도 짙은 바탕, 본문은 밝은 중립색, 강조색은 주 행동·선택·위험에 역할을 정해 제한한다. 재화의 금색과 선택의 색을 구별하고 기호·텍스트를 함께 사용한다.
- 카드·버튼·정보판은 공통 모서리·테두리·그림자 규칙을 사용한다. 배경의 돌 질감 위에 작은 본문을 직접 올리지 않는다. 작은 한글은 Light, 제목·행동은 Bold를 기본으로 실제 렌더를 비교한다.
- 타이포는 제목/행동/본문/보조의 네 단계, 간격은 공통 배수로 정리한다. 긴 유닛명은 이름 영역에서 줄바꿈하고 행동 버튼의 높이는 고정한다. 글자 자동 축소로 겹침을 숨기지 않는다.
- 내부 시안 목표: 핵심 터치 영역은 최소 48×48 논리 화면 단위, 본문은 작은 폰에서도 읽히는 크기로 검증한다. 이는 외부 표준 인용이 아닌 프로젝트 검증 목표이며 Canvas 1080×1920의 48px로 그대로 적용하지 않는다.
- 9:16 외 긴 화면, Safe Area, 360~430 논리 폭의 시안을 확인한다. 준비·유닛 선택·배치 불가·전투·상점 가득 참·결과를 각각 캡처하고 겹침/잘림/터치 영역을 점검한다.
- 첫 사용자 3~5명에게 교체 2장, 잠긴 카드 확인, 보유 카드 배치 취소, 이동/머지/교환, 상점 구매를 수행하게 한다. 오조작·막힌 입력·도움 요청을 기록한다. 추가 설명 없이 과제를 마치는지와 각 버튼의 결과를 예측하는지를 완료 판단으로 삼는다.

**구현 범위:** 먼저 공통 화면 구조·상태 표시·오입력 방지를 완성하고, 그다음 전환 연출·사거리·보스 예고를 붙인다. 강화 이펙트·데미지 숫자·추가 메뉴는 핵심 조작을 가리지 않는지 확인한 뒤 진행한다.

## 16. UX 개편 이후 발전 계획 (2026-09-08)

> **추가 기획, 미구현.** 이번 점검은 코드·직렬화된 Game 씬·Git 이력 대조다. 새 런타임 테스트나 실기기 플레이는 수행하지 않았다. 아래 목표는 첫 검증 가설이며 출시 기준 또는 밸런스 확정값이 아니다.

### 16.1 현재 도달점과 다음 목표

기본 조작을 설명할 화면 구조가 생겼다. 이제 **위협을 읽음 → 손패·보드 선택 → 전투 관찰 → 다음 선택 수정**이 한 흐름으로 이어져야 한다. 어두운 투기장 테마는 유지하고, 정보판을 더 늘리기보다 상황 카드·이번 적·결과 비트를 활용한다.

현재 `Game.unity`에는 ActionBarController·ThreatPreview·RoundBreakScreen·SafeAreaFitter 각 1개와 ButtonSkin 9개가 연결돼 있다. 결과 비트의 `DismissBreak`는 재호출을 막지만 이는 전체 UI 입력 안전성의 증거가 아니다. `ThreatPreview`는 적 타입별 합계만 제공하며, `RoundSummary`는 남은 적 총수·라이프 손실·Joker·다음 Act를 담는다. `RunStats`의 최고 유닛은 명목 DPS 기준이다.

### 16.2 P0 — 개편을 실제 터치에서 마감한다

- 교체 → 확정 → 배치 → 전투 → 결과 → 상점 → 새 손패의 상태표를 하나의 회귀 체크리스트로 관리한다. 자동 진행과 탭이 겹쳐도 전이·소비·손패 딜은 한 번이어야 한다.
- 결과 비트와 랜덤 소환 오버레이가 열린 동안 뒤쪽 보드·판매·조커·전투 시작으로 입력이 통과하지 않는지 확인한다. 결과를 닫은 동일 터치가 상점 구매나 카드 선택으로 이어지지 않아야 한다.
- 360~430 논리 폭의 세로 화면과 노치·하단 제스처 영역에서 가장 긴 유닛명, 상세 펼침, Chip 부족 사유, 보유 카드 3장을 확인한다. SafeAreaFitter가 붙은 컨테이너뿐 아니라 상점·결과·소환 패널도 개별 확인한다.
- 버튼의 눌림·처리 중·비활성 상태를 구분하되 추가 확인 팝업을 기본값으로 삼지 않는다. 처리 중 피드백은 실제 비동기 처리 구간에만 둔다.

**통과 기준:** 위 상태에서 잘린 행동명·가려진 주 버튼·의도하지 않은 재화 소비·중복 전이가 없다. 발견 건은 재현 단계와 화면 크기를 남긴다. 규칙 테스트 통과와 터치 검증을 별개로 기록한다.

### 16.3 P1 — 전투 회고를 다음 준비에 남긴다

**사용 장면:** 시간 초과 결과가 지나간 뒤 “무엇이 남았지?”를 확인하고 이번 손패의 역할을 다시 판단한다.

- 전투 정리 전에 마지막 웨이브의 결과를 불변 스냅샷으로 저장한다. 웨이브·결과·종류별 미해결 수·보스 잔존·실제 라이프 전후 차이·실제 Joker 증가를 포함한다. 미스폰 적이 미해결 수에 포함되는 경우 살아 있는 적과 구분한다.
- 다음 준비의 상황 카드에 접힌 `직전 전투` 한 줄을 제공하고 탭하면 상세를 펼친다. 새 전투 시작 시 접고 다음 결과로 교체한다. 최종 패배 화면도 같은 스냅샷을 사용한다.
- 예: `시간 초과 · 라이프 -2` / `남은 적: 러너 3, 탱커 1`. 아직 측정하지 않은 “화력 부족”, “배치 실수”, “MVP”는 붙이지 않는다.
- 기존 이번 적 텍스트는 수량을 유지하며 선택 시 특성 한 줄을 제공한다. 정보가 많으면 상세로 접고 손패를 밀어내지 않는다. 역할 안내는 사거리·공격 패턴의 사실만 설명한다.

**연결 지점:** CombatContext 종료 스냅샷 → GameFlowController.RoundSummary → RoundBreakScreen·상황 카드·ResultScreen. 표시 로직에서 보상을 다시 계산하거나 지급하지 않는다.

**통과 기준:** 성공·일반 시간초과·보스 잔존·최종 패배 모두 실제 정산과 표시가 일치한다. 다음 손패가 나와도 직전 결과가 바뀌지 않는다. 관찰 참가자가 손실과 보상을 구별하고 다음에 바꿀 선택을 하나 설명할 수 있다.

### 16.4 P1 — 첫 플레이에서 포커와 디펜스를 연결한다

첫 손패·배치·합치기 기회·상점에서 별도 안내 팝업을 표시한다. 기존 정보판 속 한 줄 안내는 인지가 어렵다는 플레이 피드백으로 교체했다. 화면 전체 차광막과 독립 창, 큰 제목, 다음 행동 버튼으로 안내임을 구분한다. 읽는 동안 전투와 뒤쪽 입력을 멈추며, 메뉴를 중첩해서 열어도 안내를 닫기 전에는 진행이 재개되지 않는다. 각 안내는 런당 한 번만 표시하고 메뉴의 도움말에서 핵심 규칙을 다시 확인한다.

| 발생 조건 | 안내할 한 가지 | 종료 조건 |
|---|---|---|
| 첫 손패, 교체 전 | 현재 족보가 어떤 유닛이 되는지, 덜 교체하면 Chip을 얻는다는 관계 | 손패 만들어 보기 버튼 |
| 첫 배치 대기 | 빈 칸 배치와 사거리 확인 | 배치해 보기 버튼 |
| 실제 동일 유닛·성급 쌍이 처음 생김 | 머지 가능한 상대와 다음 성급 | 합쳐 보기 버튼 |
| 첫 상점 | 선택은 확인, 구매는 Chip 소비, 보유 카드는 다음 교체 단계에서 사용 | 상점 둘러보기 버튼 |

합칠 상대가 없으면 합치기 안내를 표시하지 않는다. 상점 안내는 구매를 강제하지 않는다. 튜토리얼을 위해 족보·드롭·상점 가격·보상을 바꾸지 않는다. 안내는 건너뛰기 가능하고 상세 도움말에서 다시 읽을 수 있게 한다.

**통과 기준:** 포커 숙련도가 다른 3~5명의 첫 플레이에서 확정→배치를 진행자가 대신 설명한 지점, 교체와 보유 카드 사용을 혼동한 지점, 구매를 취소하고 싶었던 지점을 기록한다. 이해 실패가 반복되는 문구·배치를 먼저 수정한다. 이 표본으로 승률을 추정하지 않는다.

### 16.5 P2 — Act의 차이와 한 판의 길이를 검증한다

- 현재 Act 예고는 코드의 고정 문구다. 웨이브 에셋을 기준으로 타입 구성·총 HP·스폰 간격·제한시간을 비교해 문구와 실제 압박이 맞는지 확인한다. §14.4의 구간별 역할은 목표이며 입증된 체감이 아니다.
- 첫 측정은 로컬 기록으로 준비·전투·상점·결과 대기시간과 종료 웨이브·이유를 구분한다. 기존 ElapsedSeconds 하나로는 조작 고민과 전투 대기를 나눌 수 없다.
- 1.8초 결과 비트는 49회 모두 자동 진행하면 최대 약 88.2초의 표시 시간을 만든다. 이는 실제 런 측정값이 아니며, 탭 사용률·문구 이해도를 본 뒤 길이를 조정한다.
- 같은 시드 비교를 하려면 손패·상점·랜덤 소환의 난수 경로를 함께 고정할 수 있어야 한다. 현재 seedSource만 기록했다고 재현 가능하다고 간주하지 않는다.
- 단조로운 구간이 확인되면 기존 적 조합·밀집도·스폰 간격으로 한 Act씩 변화를 시험한다. 경제 변경·새 적 능력·배속은 별도 가설로 분리한다.

**통과 기준:** 중단 지점과 시간 부담, Act별로 달라진 선택을 실제 런 기록으로 설명한다. 자동 정책 결과와 사람 관찰을 함께 남기고 M12 사람 플레이테스트 완료 여부를 판정한다.

### 16.6 이후 후보와 착수 순서

**당시 권장 순서:** P0 입력·레이아웃 마감 → 직전 전투 회고와 첫 플레이 안내 → 실제 런 관찰 → Act 데이터 조정. 회고·첫 안내 구현 이후의 최신 실행 순서는 §17.7을 따른다.

체크포인트는 손패·덱/난수·교체 잠금·보유 카드·보드·배치 대기·상점 구매·정산 상태를 함께 복원해야 한다. 전투 직전 복귀는 전투 중 보드 조작·소비를 되돌리는 정책이므로 구현 전에 복구 경계를 확정한다. 로컬 최고 도달 기록은 이후 재도전 동기로 검토하되 능력치 보상은 붙이지 않는다. 장비·특전 복원·메타 성장·엔드리스는 계속 보류한다.


## 17. 전체 게임 루프 개선 계획 (2026-09-13)

> **2026-09-13 구현 진행:** LOOP-01·TRACK-01 및 HAND-01 비교 프로토타입을 코드·씬에 반영했다. 구현/검증 범위와 남은 게이트는 §17.8을 따른다. 아래 현재 상태 표는 착수 전 점검 기록이다. 현재 구현된 UX-09 회고와 UX-10 첫 안내를 다시 개발 대상으로 세지 않는다. 아래 보조 규칙과 지급 수치는 프로토타입 가설이다. Game 씬에는 3장 선택 안을 시험 적용했고, 기존 상점·유지 보너스 상한·유닛 수치는 유지한다. 이후 실행 우선순위는 본 절을 따른다.

### 17.1 현재 부족한 연결과 목표 루프

| 구간 | 현재 확인한 상태 | 개선 목표 |
|---|---|---|
| 시작 | 빌드 목록은 Boot→Game, Boot는 카메라만 있음. Scripts에서 타이틀 로딩 경로 없음 | 빌드 실행만으로 타이틀→게임에 진입 |
| 설정·중단 | 옵션 저장·일시정지·타이틀 복귀 경로가 없음 | 언제든 소리 조절, 안전하게 중단/복귀 |
| 카드 선택 | 일반 교체는 자리당 1회, 한 번 바꾸거나 보유 카드를 놓으면 잠금 | 아까운 손패를 능동적으로 완성할 제한된 기회 |
| 경제 | 실제 Economy.asset은 유지 보너스 상한 3, 랜덤 소환 6 Chip/라운드 1회, 상점 장당 4 Chip | 기존 무교체 보너스와 족보 도전 사이의 선택을 보존 |

| 회고·안내 | RoundRecap·잔여 적 상세·OnboardingGuide 4종 구현 | 실제 사람이 읽고 다음 선택에 쓰는지 검증 |

목표 흐름: **Boot 초기화 → Title → 새 런 → 손패/보조 선택 → 배치 → 전투 → 회고 → 상점 또는 다음 손패 → 최종 결과 → 재도전/타이틀.** 런 중에는 일시정지→옵션/계속/타이틀 복귀가 열린다. 이어하기는 저장 검증을 통과한 뒤 별도 노출한다.

### 17.2 LOOP-01 — 타이틀·옵션·일시정지 (P0)

**화면:** 배경은 기존 투기장 아트를 재사용하고 게임 타이틀, `게임 시작`, `옵션`, `도움말`, 지원 플랫폼의 `게임 종료`를 둔다. 정식 게임명·새 로고 제작은 별도 아트 작업이며 시작 흐름을 막지 않는다. 이어하기 데이터가 없는데 버튼만 먼저 만들지 않는다.

- Boot는 공통 설정 초기화 후 Title을 한 번 로드한다. Title→Game은 전환 중 버튼을 잠가 중복 로드를 막는다. 씬 이름/경로 참조를 사용하고 기존 buildIndex 숫자 가정도 점검한다. 에디터 Game 직접 실행도 기본 설정으로 동작해야 한다.
- 1차 옵션은 마스터/BGM/SFX 음량과 음소거, 기본값 복원. 설정은 로컬에 저장하고 다음 실행·씬 이동에도 유지한다. 마스터와 개별 음량은 곱으로 적용하며, 기존 musicVolume·ducking과 중복 감쇠되지 않도록 오디오 경로를 하나로 정한다.
- 타이틀과 게임은 같은 설정 UI를 사용한다. 도움말은 족보→유닛·일반 교체·보유 카드·머지·상점의 짧은 설명을 다시 읽는 곳이다. 현재 OnboardingGuide의 세션 한정 표시를 장기 완료 저장으로 바꾸는 일은 별도 구분한다.
- 게임의 메뉴 버튼/뒤로 입력은 일시정지를 연다. 전투 시간·스폰·유닛 공격·랜덤 소환 연출·결과 자동 전이를 함께 멈추고, 모달 뒤 카드/보드 입력을 차단한다. 메뉴 UI는 정지 상태에서도 반응해야 한다. BGM 일시정지/작은 음량 유지 중 하나를 일관되게 적용한다.
- `타이틀로`는 저장 기능이 없는 1차 버전에서 `현재 진행을 포기하고 타이틀로 돌아갈까요?`를 명시한다. 취소하면 정지 메뉴로 돌아간다. 복귀/재시작 후 시간 배율·오디오 덕킹·선택·이벤트 구독이 정상 초기화돼야 한다.
- 결과 화면은 `다시 도전`과 `타이틀로`를 제공한다. 앱 종료는 플랫폼에서 지원하는 경우만 표시하며, 에디터에서 종료 버튼이 반응하지 않는 것을 빌드 동작과 혼동하지 않는다.

**완료 기준:** 실제 빌드 첫 실행→시작→옵션 변경→일시정지/계속→결과→재도전/타이틀 왕복. 옵션 저장·기본값 복원, 연타 1회 전이, 전투/결과 비트/상점/소환 중 정지 복귀를 확인한다. 한 번의 정상 런 외 의도적 포기·앱 재실행도 검사한다.

### 17.3 TRACK-01 — 배경과 적 이동 경로 정합 (P0)

현재 `TrackPosition`은 반폭 3.4·반높이 2.4, 길이 23.2인 사각형이다(보드 CellSize 1, TrackMargin .9). `EnemyInstance.Position`과 이동 속도, CombatContext의 관통 뒤쪽 거리, CombatScreen의 방향 선택에 쓰인다. **스프라이트 위치만 예쁜 길로 옮기면 사거리 판정과 보이는 위치가 갈라진다.**

1. 게임 화면에 실제 경로 선·일정 거리 간격의 점·적 발 기준점·사거리 링을 겹친 진단 캡처를 만든다. 배경 본체, TrackLoop 오버레이, 보드 원점/스케일을 함께 확인해 어떤 길을 걷게 할지 먼저 확정한다. 현재 진단은 코드상 사각형 확인이며 시각 오차량 실측은 아직 하지 않았다.
2. 우선 기존 경로에 아트 위치/크기만 맞출 수 있는지 확인한다. 그것으로 해결되지 않으면 단일 TrackPath 데이터(첫 버전은 둥근 사각 경로 또는 제어점 경로)를 사용한다. 범용 스플라인 에디터 제작부터 시작하지 않는다.
3. 경로 데이터가 위치·접선·누적 길이를 제공하고 로직과 뷰가 같은 데이터를 읽게 한다. 이동은 곡선 매개변수가 아니라 누적 거리 기준으로 계산해 코너에서도 속도가 일정하게 유지되게 한다. 기존 랩/진행도 의미와 앞선 적 우선 타깃 규칙을 보존한다.
4. 방향별 4장 아트는 접선 방향을 기준으로 고르며 경계 근처에서 깜빡이지 않게 전환을 안정화한다. 적 발·그림자는 길 중심을 따라가고 큰 보스의 몸이 벽을 침범하는지도 별도 확인한다.
5. 관통의 트랙상 뒤쪽 거리, 스폰 간격·한 바퀴 시간, 사거리 내 체류시간·유효 피해량을 기존 경로와 비교한다. 경로 길이 변화에 맞춰 속도나 사거리를 자동으로 일괄 보정하지 않는다. 시각 정합 완료 뒤 밸런스 조정 필요성을 따로 판단한다.

**완료 기준:** 네 직선/코너/루프 이음부에서 발이 길 밖으로 벗어나지 않고 순간이동·속도 튐·방향 떨림이 없다. 15칸 각각의 최소/최대 사거리에서 표시와 판정이 일치하며, 실제 유닛 공격·관통·보스 이동을 확인한다. 9:16·긴 화면에서 월드 아트와 경로 정합이 유지돼야 한다. 사람 플레이 밸런스 측정은 이 경로를 확정한 뒤 수행한다.

### 17.4 HAND-01 — '상위 족보를 직접 만든다'의 방향

문제 가설: 일반 교체가 끝나면 아까운 4장 손패를 더 밀어붙일 수 없고, 상점은 특정 카드가 필요해지기 전에 구매한다. 무교체에는 즉시 Chip 보상이 있어 족보 도전보다 안전한 수급이 매력적일 수 있다. 후자는 관찰로 검증할 가설이며 현재 전략 우열을 단정하지 않는다.

목표는 최상위 족보를 정기 배급하는 것이 아니라 **손패를 보고 노릴 대상을 정하고 마지막 카드를 고르는 순간**을 만드는 것이다. 원페어/투페어 머지의 가치와 최고 족보의 희소성도 유지한다.

| 방식 | 장점 | 위험 | 결정 |
|---|---|---|---|
| 추가 교체: 일반 교체한 자리 1곳을 다시 무작위 교체 | 규칙이 간단하고 한 번 더 도전 가능 | 다시 실패하면 기대만 늘고 선택감은 약할 수 있음 | 비교 프로토타입 B |
| 정해진 범위(숫자대/색 등)에서 한 장 교체 | 방향을 정하는 감각 | 특정 범위가 정답이 되거나 후보 풀이 고갈됨 | 3장 선택 후 필요하면 비교 |
| 특정 무늬/정확한 숫자만 지정 | 상위 족보를 강하게 노릴 수 있음 | 4장 같은 무늬에서 무늬 지정은 플러시 보장, 정확한 숫자는 포카드 등을 쉽게 보장 | 첫 버전 제외 |
| 남은 덱 3장 공개→1장 선택 | 확률과 선택이 공존, 서로 다른 족보 경로를 비교 | 공개·소비·취소 규칙과 카드 중복 관리 필요 | **권장 프로토타입 A** |
| 실패 누적 후 상위 족보 확정 지급 | 최저 경험 보장 | 실패 유도, 조립보다 보상 수령이 중심 | 보류 |

**표시 이름: '추가 교체'** (기존 ‘승부 교체’에서 변경). 기존 Chip과 별도로 런 안에서만 쓰는 횟수형 기회를 제공한다. 과거 딜러 특전의 영구 패시브를 복원하거나 상점의 보유 카드를 대체하지 않는다. UI는 추가 재화 HUD보다 손패 옆 `추가 교체 1회` 액션으로 시작한다.

### 17.5 추가 교체 A — 첫 실험의 정확한 규칙

**지급 가설:** 런 시작 1회, W6·11·16…46에 처음 진입할 때 1회 보충, 보유 상한 2회. 클리어 여부와 무관하게 정해진 진행 이정표에서 지급해 실패→상점 부재→보조 부재의 연쇄를 피한다. 중복 진입/복구로 다시 지급하지 않도록 이정표별 지급 상태가 필요하다. 실제 총 지급량은 사람이 상위 족보를 경험하는 빈도로 조정하며 정식 수치로 확정하지 않는다.

- Exchange에서만 사용, 한 라운드에 최대 1회. **일반 교체로 이미 잠긴 자리 1곳만** 재도전할 수 있다. 아직 일반 교체하지 않은 자리와 보유 카드 배치로 잠긴 자리는 대상이 아니다. 먼저 무료 교체를 쓰게 해 무교체 Chip 보너스를 그대로 챙기면서 강한 교체만 쓰는 행동을 제한한다.
- `추가 교체` → 교체할 자리 선택 → 비용과 결과 규칙 확인 → `후보 3장 공개` 순서. 공개 전 취소는 무료다. 기존 보너스와 사용 후 보너스를 함께 보여준다.
- 공개 시 기회 1회와 라운드 사용권을 소비하고, 실제 남은 덱에서 서로 다른 최대 3장을 꺼낸다. 다음부터는 공개된 후보 중 1장으로 반드시 교체하며, 후보를 보고 취소해 다시 뽑는 기능은 없다. 공개 후에는 손패 확정·일반 교체·보유 카드 사용을 잠시 막는다. 일시정지는 가능하되 복귀하면 같은 후보가 남는다.
- 선택 시 기존 카드와 미선택 후보는 이번 라운드의 버린 카드가 되고 재추첨 대상에서 제외한다. 선택된 카드는 해당 자리에 놓이고 다시 잠긴다. 이번 라운드에 이미 나온 카드·보유 카드가 후보에 중복 등장하면 안 된다.
- 보너스 계산에는 추가 교체 1장으로 산입한다. 현재 `max(0,3-UsedExchanges)` 규칙에 따라 +2라면 +1, 이미 0이면 0이다. 공개 UI에 이 변화와 기회 소비를 함께 표시한다. 후보 3장을 봤다고 교체 3장으로 세지는 않는다.
- 후보가 1~2장뿐이면 실제 남은 수만 공개한다. 0장이면 공개를 막고 횟수를 차감하지 않는다. 덱 고갈 사유를 표시한다. 예외/연타로 기회만 잃거나 후보만 중복 뽑히지 않도록 트랜잭션으로 처리한다.
- 정확한 승률/완성 보장은 표시하지 않는다. 후보를 탭하면 그 카드로 바뀐 **5장 전체**의 족보·유닛·머지 가능 여부를 미리 보고 `이 카드로 교체`를 누른다. 높은 족보 순으로 자동 선택하지 않는다.

**예시:** 하트 4장을 유지하고 나머지 1장을 일반 교체했는데 실패했다. 추가 교체로 공개한 후보에 하트가 있으면 플러시를 완성할 수 있고, 없으면 다른 족보나 다음 배치에 맞는 카드를 고른다. 후보 3장 모두 맞지 않을 수도 있으며 보조 성공을 보장하지 않는다.

**구현 경계:** RoundContext의 bool 잠금만으로는 일반 교체/보유 카드 배치의 이유를 구분할 수 없다. 잠금 이유와 추가 교체 단계·후보 상태를 로직에서 관리한다. Deck은 남은 덱을 안전하게 꺼내는 API를 제공하고 UI가 별도 카드 풀을 만들지 않는다. StageContext에 런 기회/지급 이정표, RoundController에 이벤트, RoundScreen/CardView에 후보 트레이를 연결한다. 위 값은 체크포인트 저장 대상에 포함한다.

### 17.6 비교·밸런스 검증과 상점 역할

**한 번에 둘을 출시하지 않는다.** A(3장 선택)와 B(무작위 추가 교체 1장)를 같은 지급·사용 대상·보너스 비용으로 비교한다. 기존 규칙도 대조군으로 남긴다. A/B의 드로우 소비량 차이는 기록하며, 같은 초기 시드를 사용해도 분기 뒤 난수 소비가 달라질 수 있음을 명시한다.

- 자동 비교: 초반 W1~10/Act별 확정 족보 분포, 스트레이트·플러시·풀하우스·포카드·최상위 족보를 각각 분리, 첫 상위 족보까지 라운드, 도움을 쓴/안 쓴 결과, Chip·보유 카드 구매/사용·랜덤 소환·머지 수와 클리어 결과를 측정한다. 뽑힌 기회만 세지 말고 최종 확정한 족보를 센다.
- 사람 관찰: 3~5명에게 현재 규칙과 후보를 짧게 비교하게 하고 `왜 이 자리를 바꿨는지`, `후보 중 무엇을 골랐는지`, `실패해도 선택했다고 느끼는지`를 묻는다. 통계적 승률 판정으로 쓰지 않는다. 교체 단계 소요시간·규칙 질문·잘못 소비한 횟수도 기록한다.
- 필수 정확성: 동일 카드 중복 0, 연타 중복 지급/차감 0, 공개 전 취소 미소비, 공개 후 재추첨 불가, 보유 카드 잠금 재교체 불가, 상한·라운드 제한·보너스 계산·최종 확정 1회. 저장 구현 시 공개 후보와 지급 상태를 그대로 복원한다.
- 채택 조건: 플레이어가 도움의 결과와 비용을 이해하고, 기존보다 의도한 족보를 완성하는 장면이 늘며, 매번 무조건 쓰는 의식이나 반복 실패 연출이 되지 않는다. 최상위 족보 빈도와 상점 가치가 크게 무너지면 공급량·후보 수·대상 조건부터 조정한다. 밸런스 임계치는 대조군 측정 후 확정한다.
- 상점은 **미리 확보하는 확정 카드**, 추가 교체는 **지금 손패에 쓰는 불확실한 기회**로 구분한다. 첫 실험에서 상점 가격·판매가·유지 보너스 상한·랜덤 소환 풀을 동시에 바꾸지 않는다. 별도의 Chip 구매와 실패 보상은 이후 후보이며 기본 지급과 중첩하지 않는다.

### 17.8 구현 및 검증 상태 (2026-09-13)

- **LOOP-01 구현:** Boot→Title→Game, 공통 옵션/도움말, 일시정지·계속·포기 확인, 최종 결과→타이틀/재도전. 마스터/BGM/SFX·음소거 설정은 로컬 저장하며 기존 믹스 음량에 곱한다. 일시정지는 시뮬레이션 시간·보드 포인터 입력·오디오를 멈춘다. 앱이 백그라운드로 가면 자동 정지한다. 실제 종료는 데스크톱 플랫폼에 표시한다.
- **TRACK-01 구현:** `TrackPath.Arena`의 반폭 3.2·반높이 1.95·반지름 1.2를 공통 위치/접선/길이에 사용한다. 거리 기준 이동이므로 코너에서 속도가 변하지 않는다. 기존 23.2에서 18.5398로 길이가 줄었다(같은 속도에서 한 바퀴 약 20.1% 단축). 적 발 pivot=0과 진단 경로를 겹쳐 배경 길 위에 놓이는 것을 확인했다.
- **경로의 밸런스 영향:** 15칸×현재 사거리 2.5/3/3.5/4를 각각 10,000점 등거리 표본으로 비교했다. 사거리 2.5의 한 바퀴 내 체류 비율은 슬롯별 12.1~29.9%→25.2~56.1%로 증가했다. 이는 기하학적 체류 비율이며 실제 유효 DPS·승률 측정은 아니다. 웨이브/속도/사거리 수치는 함께 바꾸지 않았다. 결과는 `Artifacts/GameLoop/track-comparison.json`(로컬)에 보관한다.
- **HAND-01 시험 적용:** 일반 교체 잠금과 상점 배치 잠금을 구분하고, 공개 시 횟수 차감·후보 중복 방지·공개 후 확정/추가 추첨 차단·최종 한 장 선택을 로직에서 처리한다. 후보별 전체 손패·족보·소환 유닛·현재 보드 머지 가능 여부·유지 보너스 프리뷰를 제공한다. 일반 교체 전에는 추가 교체 버튼에 사용 조건을 표시한다. 일반 교체 대상이 생기면 후보 팝업을 열 수 있고, 공개 전에는 무료로 닫을 수 있다.
- **A/B 전환:** Game 씬의 `RoundController.assistMode`를 Inspector에서 `Disabled`(기존), `ChooseThree`(기본 후보), `RandomOne`으로 설정하고 새 런을 시작한다. 같은 런에서 조건을 바꾸지 않는다. 둘을 동시에 제공하지 않으며 정식 채택·지급량 확정은 사람 비교 후 결정한다.
- **RUN-01 기록 기반:** `RunJournal`이 `Application.persistentDataPath/RunJournals`에 단계별 시간(정지 제외), 확정 손패·족보, 교체 수·보조 사용·Chip·보유 카드 수·배치/머지 이벤트를 JSON으로 남긴다. 손패 생성 시드는 라운드별 기록이며 상점/랜덤 소환까지 포함한 전체 런 재현 키가 아니다. 로그는 이어하기 저장 파일이 아니다.
- **검증:** EditMode 241/241 통과. Boot→Title→Game→개발 스킵을 통한 최종 결과→Title 연결, 설정 씬 간 유지, 공개 후보 정지/복귀 시 동일, 공개 뒤 확정 차단, 팝업 뒤 Raycast 및 CanvasGroup 키보드 입력 차단/중첩 복원, 전투 정지 전후 경과시간/적 진행도 동일 확인. 360×800 긴 화면 옵션/후보 선택 영역도 확인했다. 개발 스킵은 정상 사람 50웨이브 플레이를 대신하지 않는다.
- **남은 게이트:** 정상 사람 런과 A/B 선택감·경제 비교, 폰/Safe Area 실제 터치 및 보스 시각 검증. **SAVE-01 저장·이어하기는 미구현**이며 계획의 사람 비교 다음 단계로 남긴다. 타이틀 복귀 전 현재 런을 잃는다는 문구를 표시한다. 실험 채택 전 Act·경제·메타 성장까지 확장하지 않는다.

### 17.9 첫 플레이 피드백 반영 (2026-09-13)

- 추가 교체를 “일반 교체로 바뀐 카드 한 장을 다시 바꾸는 기능”으로 설명한다. 카드 선택 → 후보 확인 → 한 장으로 교체 순서를 항상 표시한다.
- 공개 전에는 물음표 후보 카드로 결과가 나올 위치를 보여준다. 대상이 없으면 먼저 일반 교체를 하도록 안내하고, 대상 카드에는 교체 가능/선택 불가 상태를 쓴다.
- 공개 버튼에 기회 1회 소모를 명시한다. 공개 전 보너스 전후 값과 공개 후 한 장 선택 의무를 안내한다. 공개 전 돌아가기는 무료이며, 선택 후 족보·유닛·합치기 프리뷰는 유지한다. 후보 수는 A/B 설정에 맞춘다.
- 이번 변경은 설명·시각적 분리 개선이며 후보 확률·지급량·유지 보너스 계산은 바꾸지 않는다.

### 17.10 교체 행동의 위치와 위계 (2026-09-13)

- 분리되어 있던 큰 추가 교체 버튼을 없애고 하단 행동 바에 **일반 교체 / 추가 교체 / 손패 확정** 순서로 배치한다. 추가 교체는 선택 사항이며 확정 없이도 일반 교체를 계속할 수 있다.
- 세 버튼은 위치를 유지한다. 추가 교체는 일반 교체 전·기회 소진·이번 손패 사용 완료 사유를 버튼 안에 표시하고 비활성화한다. 사용 가능할 때 남은 기회를 표시한다.
- 버튼 첫 줄은 행동 이름, 둘째 줄은 대상/조건/보너스로 통일한다. 손패 확정은 주 행동 색, 두 교체는 보조 행동 색을 쓴다. 1080 기준 버튼 높이 140으로 터치 영역을 넓힌다.
- 행동 바 위 안내는 현재 가능한 다음 행동을 설명한다. 모든 자리를 일반 교체했더라도 ‘더 바꿀 카드 없음’ 대신 ‘일반 교체 완료’라고 써 추가 교체와 혼동하지 않게 한다.
- 추가 교체 대상이 한 장뿐이면 팝업에서 자동 선택한다. 여러 장이면 직접 고른다. 자동 선택은 후보 공개나 기회 소비를 실행하지 않는다.
